- 历史先提交，再移除活动记录并通知完成；数据库暂时失败时保留已知结果，普通结果队列和 manager 结果缓存都可重试。回执丢失后相同终态保留原完成时间，冲突终态拒绝覆盖。迟到取消、Worker 失败或调用方复用输出容器不能替换已知计算结果；排队取消在写库未确认时保留取消意图并禁止派发，后台收集线程重试。旧队列清空也记录取消历史。查询及旧队列状态读操作转入线程，避免直接在 HTTP 事件循环内等待队列锁/数据库。历史默认保留，清理策略仍待补齐；数据库失败期间主进程退出的未提交结果按后续持久归属规则处理为不确定执行。
- 迁移 0025 为旧编辑器增加内部接收/派发/运行记录，沿用原 Task ID、工作区 scope、请求 Graph 和公开 Task 状态。`/api/queue` 只有接收记录确认提交后才返回 202；DB 回执未知返回可重试 503 和原 task_id，不声明 accepted。后台能将已提交但尚未进入内存队列的本实例接收记录补回；接口提示先检查该 ID，不保证无幂等键的新请求重试会自动合并。
- TaskQueue 把请求交给调度调用者之前就持久化可能派发的事实，兼容直接从旧队列取任务再送入 Worker 的调用方式；正式发送 IPC 前再核对归属/取消。DB 未确认时调度线程保留任务并重试，不能先执行。确认 IPC 满额而未发送时归还为待派发；发送结果未知时保持可能执行，不自动重算。工作区接收序号通过原元数据表事务分配，恢复保持优先级及同优先级顺序；启动扫描跨越 100 条内部批次，后台按批次检查。
- 旧 Run 复用既有 ControlGuard：Server 持有一份退出证明，真实 Worker 在确认接收和加载 Graph 前独立加入，直到计算/释放及结果交接结束才释放。恢复须拿到原归属的排他锁并核对同系统启动、设备/inode 和标识，持久撤销后才能处理记录。仍有子进程持有时、文件缺失或副本不匹配时均不恢复；迟到 Worker 加入被撤销归属会被拒绝，不依赖 PID 或租约超时推断退出。
- 确认原归属退出后，尚未交给调度调用者的请求可转给一个新 Server 继续；已派发/运行而未提交结果的请求记为 FAILED，已有取消意图则为 CANCELLED，禁止自动重跑。终态历史和活动记录的终态转换在同一事务内；旧活动记录只保留身份和生命周期字段，重复的大请求正文被清空。多个 Server 同时恢复用条件更新确定唯一领取者；构造中途失败也释放退出证明，下一实例可以继续恢复。
- 原队列查询能显示本工作区其他归属的未完成任务；取消只持久化对应任务意图，由实际持有者传达给 Worker，或等待确认退出后结束，不能误转发给新实例的 Worker。退出证明受限的记录保持未完成，不伪造终态。当前证明支持同工作区、同次 Linux/macOS 系统启动；整机重启、异主机、Windows 及未知旧版本仍须对应恢复机制。原生输出和已产生文件的保留、长期记录清理及请求幂等仍需补齐。
- 每个入口独立 TaskQueue 和 Worker，限制入口与整个 Server 在途任务数量。
- 可选 `Server(device_limits=...)` / `--device-limits` 为新增 Server 入口接入常驻模型预算。execution.devices 声明每 Worker 的完整设备组，execution.memory_bytes 声明每设备常驻内存；按 workers 相乘，多设备在同一事务预留。工厂、Graph 加载、预热前检查，失败不加载候选；Reload 同时保留新旧模型直到旧 Worker 实际关闭。预算缺失、策略冲突或容量不足明确拒绝。
- 迁移 0021 在 SQLite/MySQL/PostgreSQL 保存内部预算及占用归属。默认按持久工作区协调，显式 host 作用域要求共享 DB、namespace、稳定 host_id 与物理设备 identity；不同别名映射同一物理身份共享预算。不同默认工作区互不影响，不依赖 Redis。已有占用时不能用不同预算悄悄覆盖策略，全部释放后可重新配置。
- 常驻占用没有心跳/租约过期回收。控制进程和隔离 Worker 在模型初始化前共同持有退出证据，父进程退出而子进程仍运行时继续占用；确认全部进程退出后才回收，并拒绝迟到子进程加载。自动恢复要求同一 Linux/macOS 内核启动、可访问的原工作目录和匹配锁文件；每批最多 100 个归属，单条失败不阻塞其他模型，复制/缺失或异机证据保留未确认状态。
- 资源申请/释放回执丢失用同一归属重试。正常关闭等待物理 Worker；数据库无法确认释放时保留记录，之后凭退出证据对账。管理查询复用 `/api/server?include_resources=true` 返回声明预算与占用，入口描述增加设备和每 Worker 内存声明；未把这些数值当作硬件监控。CPU 示例 `demo/server/device_limits.py` 验证两个入口及更新余量。
- 设备 max_concurrency 限制 Deploy 实际调用并发，线程、进程、并发/引擎和动态合批复用同一协调；整批只占一个设备名额，Task 身份和各项结果保持不变。多设备组原子获取，完全不同设备独立推进。reserved_slots 按已有入口名保留不可借用份额，execution.priority 每一点提前一秒，等待时间补偿防止新请求持续插队；不改变入口自身的队列规则。
- 迁移 0022 保存内部执行占用与原 Task 关联，等待使用原队列期限，检查取消及执行归属；数据库无法确认申请时不计算。运行占用直到实际算法结束才释放，释放提交故障后台重试且不改变已知结果；完整物理归属退出后同时对账残留执行占用。管理查询补充按实际调用/批计算计数的 running/waiting，不增加公开 Task 状态。请求断连不取消 Server 持有的执行。
- 独立 Start/Reload 的每个 Worker 初始化、全部预热与 Deploy 使用相同的设备名额、保留份额和优先级。等待计入现有每 Worker 启动期限，取得名额后继续使用剩余时间；等待超时不调用工厂，初始化异常时只有确认清理才释放。线程等待实际计算结束、隔离进程按期限终止、异步引擎等待取消清理；未确认关闭的占用保留。启动不创建用户 Task，复用内部执行记录；管理 running/waiting 包含初始化。Deploy 调用内的隔离 Worker 重建随该调用持有执行名额。不自动改变 Graph/算法的设备；隔离 CPU 线程设置见下文，请求临时内存协调见下文。未参与协调的进程、实际设备核验/显存查询和 GPU 实测仍未纳入；旧编辑器 Run 的资源接入见本次记录；不能据此宣布 R27/Q08/Q10–Q12 全部完成。
- execution.temporary_memory_bytes 接入现有设备预算：常驻与运行临时内存共享上限，初始化/预热和批输入准备按一个请求预留，实际批计算按有效成员数相乘。加载前保留配置最大批量及 reserved_slots 的运行余量；已有普通并发调用的实际临时内存加未使用的保留内存也必须容纳，无法容纳即拒绝候选；不自动缩小批量。等待沿用原队列/期限，实际计算结束或物理退出后释放，DB 回执丢失不会重复分配。迁移 0023 保留旧占用、新字段默认零，并修正 MySQL 大小写标识比较；管理查询显示常驻、临时、合计、剩余与运行余量。该能力依赖声明估计，未声明的临时内存不计入，不代表真实分配器/GPU 峰值限制。
- 可选 execution.cpu_threads 接入隔离 Worker，在工厂前、工厂返回后、每次 Deploy 前刷新支持的本地库线程设置；Graph init 前递归限制后端线程参数，保留更小值，原 JSON 不变。默认省略保持既有配置指纹；普通线程模式拒绝进程级修改。OpenCV GCD 经实测会忽略正数设置，已增加串行回退与效果检查；不满足上限时启动失败，旧 Worker 不受失败 Reload 影响。设置随崩溃重建和持久配置恢复，管理描述提供 cpu_threads。该功能不等于 OS 总线程配额/CPU 绑定；自定义线程、未识别库、另一份独立原生库及模块导入时的初始化仍需算法设置。当前 PyTorch、OpenMP/BLAS 效果与性能没有实机验收。

- 常驻 Graph 输入默认值恢复、输出分离、失败后重建；当前已验证顺序 Graph 的文本及 PIL 图片。
- 新增 `array` / `tensor` 字段，HTTP 使用固定的 `{dtype, shape, data}` 平铺 JSON，声明 dtype、shape（可含 null 维度）、元素数和字节上限。输入在原生分配前检查形状、长度、类型、溢出、有限值和范围；Worker 内转换 NumPy / nndeploy Tensor，输出脱离原生缓冲区后写入任务及事件。同步、异步、流式、预热和动态合批复用转换。

- 持久化请求输入、参数、结果、错误、取消请求和尝试序号；幂等键冲突检查、条件终态更新。

- 共享控制写入对临时 DB 故障和成功回执丢失使用同一次条件写入重试，期间出现新控制则拒绝旧重试。退出时未确认返回 `shared_control_unconfirmed`，本机释放不停止其他实例。副本需要一致升级；这些运行中恢复机制不能代替完整跨重启操作结果对账。HTTP 控制幂等现通过迁移 0020 的请求记录实现。
- 共享 Reload 的数据库基础已实现：迁移 0016 和内部 `shared.py` 保存同一入口的活动配置、待加载配置和实际 Worker 引用。初始化期间旧队列继续接单；确认候选 Worker 就绪后，在同一事务中切换活动配置和队列接收状态。已登记的旧队列不能被 Start 重新打开，旧任务仍按原队列领取和完成。准备期间新的 Start/Stop 会使旧切换失败；未排空任务或未确认退出的 Worker 阻止释放配置和再次 Reload。
- 配置快照复用 `server_configs` 及其文件引用，事务失败不留下半份配置；旧配置仅在任务归零且 Worker 引用全部释放后移除资源引用。实例重启读取已提交的活动配置，重复切换确认不会覆盖后来的 Stop。工作区持久化只保存入口关联，避免旧配置副本长期占用文件引用。崩溃遗留 Worker 引用不按时间自动释放。
- 内部 `shared_runtime.py` 已连接 Server 启动、Worker 初始化/预热/关闭、Reload 和后台副本跟随。相同配置再次 Reload 也使用新的内部队列，旧任务归属不变。过期副本在请求绑定前返回 `entry_changed`，就绪检查同时核对活动配置及接收状态；新 Worker 已可用但旧任务尚在排空时保持就绪。迟到的 Start 和 Stop 均拒绝操作旧队列。编辑器 Start/Update 复用同一流程，停止后更新直接准备新配置，失败保留旧停止状态。

- 共享后台恢复旧配置中尚未执行的排队任务，使用旧输入/输出绑定和独立 Worker，当前入口继续按新配置接收请求。多副本仍通过 DB 条件领取防止重复执行；其他副本已处理完并清理配置时，过期恢复观察不会留下错误状态。旧模型暂时加载失败保留原任务和名额，并有间隔重试。恢复 Worker 在待执行任务清空且自身执行结束后退出，不等待其他失联执行占用的名额。

- 引擎取消按 task_id 定位，默认等待真实计算结束；声明 `cooperative_cancel` 后可协作取消与设置协作执行期限。请求清理未结束时不释放名额，重复取消不会打断清理。任务日志上下文不会在并发请求间串扰。

- 显式批量调用提供 `Server.deploy_batch()` 与 `/v1/server/{name}/deploy/batch`，一次 1–64 条输入，逐条校验/准入/记账/返回，不新增批任务记录。支持同步与异步、条目幂等键、身份隔离、部分容量不足和错误状态重放。
- 批量接收期间发生 Reload 时，未接收条目返回冲突，已接收条目由原入口完成。Python `submit()` 返回独立的等待 Future，调用者等待超时不取消 Server 的执行归属。

- 同步批量共用一个准入后的等待窗口，逐项返回结果或 504，外层仍为 200；async/stream 不接受等待参数。共享 Redis 副本的 HTTP 等待配置不影响队列摘要。校验错误响应只返回字段位置、类型及信息，避免 NaN/Infinity 或异常上下文导致错误响应编码失败。
- 同步 HTTP 增加每 Server 连接容量（`max_sync_connections`，默认取任务总量上限），已有鉴权配置可选每 subject 上限，同身份多 key 共享；不增加公开业务实体。标准/批量/算法接口在准入前检查，满额 429 不接收任务；批量占一条，幂等重复等待按连接分别计数。
- 连接名额覆盖算法响应转换及正常响应发送，框架异常退出也释放；单次发送等待上限 5 秒。真实 HTTP 断开或 ASGI 请求取消只结束等待，独立持有的准入与任务继续执行。查询/取消/管理/异步提交保留独立通路；Redis 副本各自限制 HTTP 连接，共享任务容量保持不变。新增无身份标签的连接数/上限指标；任务/文件/速率的跨副本身份配额已接入，跨副本同步连接总额度仍需按部署需求完善。
- 断连专项发现并修复同步批量结果等待被整体保留为 Server 操作的问题：现在仅准入阶段由 Server 独立持有，结果等待随客户端结束。回归先证实旧实现留下等待者；修复后验证数据库写入期间断连仍完成全部准入，计算保持运行且无遗留结果等待者。
- 增加可解绑的内部结果观察 Future：同步超时/取消主动解绑，异步 HTTP 和 SSE 在接收后立即解绑不再使用的观察对象。当前 Python 3.14 的 shield/wait 等待关系会将退出的等待任务保留到原 Future 完成，现不直接将 HTTP 等待者挂到长运行的计算 Future 上。弱引用回归在原计算仍运行时验证单条、批量、异步重试和流断连对象均可回收，未修改原生计算取消语义。
- 按算法能力启用动态合批：`execution.batching` 配合 handler 的 `batch_key` / `deploy_batch`，同一 Worker 的单线程完成初始化、分组与实际批计算；自动按调用身份、完整参数及算法形状键分组，每条仍是独立 Task。
- 动态合批有最大批量、首条等待上限和总在途限制；优先最早兼容组，不让后续流量延长旧请求窗口。合批等待计入排队期限，记录启动期间或线程等待期间到期也不会进入算法。取消中的实际计算保留名额，单条输出错误不影响其他有效条目，整个批次异常不隐式重试。
- Redis 领取后在实际合批前复查执行归属、取消和数据库时间；保留逐条记录、幂等和远程取消。普通 Graph、进程隔离、流式和 engine 的外层合批组合明确拒绝；引擎内部调度继续使用 engine。
- 旧编辑器 `/api` 路由（工作流、队列、文件、插件、预览、管理）与进度 WebSocket 统一检查管理权限；普通调用 API key 无法访问共享编辑器资源。API-only 不增加编辑器路由。
- 英文登录入口复用管理令牌；会话 Cookie 限定 `/api`、HttpOnly、SameSite=Strict，HTTPS 下 Secure。每进程最多 128 个会话，有效期 8 小时；只存摘要、退出和过期撤销 WebSocket，进程重启需重新登录。不同运行目录的 Server 使用不同 Cookie 名称。会话为进程内状态，编辑器需连接固定实例或使用粘性路由；尚未共享到 Redis。
- Cookie 写操作与 WebSocket 验证 Origin；CORS 改为显式来源白名单，开发代理默认使用本机。进度连接数量、绑定数量与消息大小有界。预览和下载限制在资源及模板目录；拒绝上传和工作流名称路径穿越，文件响应加 nosniff 与 sandbox。
- 前端登录一次后即可使用 Server 面板，退出或会话过期保留未保存画布，重新登录恢复进度连接。移除了重复建立进度 WebSocket 的 effect。
- 浏览器验收暴露并修复原生节点目录崩溃：SAM2 编码器未在模型加载前声明三个输出；SAM3 部分节点缺少端口类型声明。补齐声明并重新构建 segment 插件，完整 `/api/dag/info` 和枚举查询在子进程回归测试中通过；这不等同于真实 SAM 模型计算验收。

- 算法扩展增加应用内可信名称注册和按需导入；工厂返回已有 `Server.add` 参数，支持直接 Graph/JSON/代码配合算法自己的 HTTP router，不引入新的执行对象。缺少可选依赖只影响所选择的算法；普通 HTTP 请求无法注册或指定模块执行。
- 专用路由统一绑定当前入口和身份，`get_deploy` 复用标准 Deploy 的权限、幂等、排队、任务记录、异步响应及 SSE；`get_entry/get_db/get_storage/get_redis` 提供已有公共依赖。新增路由位于编辑器前端 catch-all 之前，OpenAPI 缓存随挂载失效。真实 Graph 线程/进程、标准接口重试同一任务、队列满载与 Stop、三数据库和 Redis 纳入验证。
- 示例 `demo/server/algorithm.py` 和 `demo/server/text/server/` 展示专用协议/算法实现/HTTP 路由分目录接入。当前限制：启动前挂载普通 HTTP APIRouter，不含嵌套 lifespan 或独立生命周期钩子；双向流和具体模型的兼容协议仍待补齐。代码工厂和路由由应用启动代码恢复，未自动持久化 Python 注册。

- 已观测 HTTP 完整时长/首包、准入/初始化/Worker/排队耗时、本地队列、当前及排空 Worker、容量与 SSE 连接。共享队列复用现有控制心跳的全局用量样本及采样年龄；抓取不查询外部依赖，故障时仍能查看指标。共享副本的全局用量不能相加。
- 父进程 SQL 语句、共享 Redis 命令、受管理文件操作和清理结果有耗时/结果指标；任务终态计数仅在 DB 提交回执成功后增加，幂等查询、事务回滚和重复终态提交不增加。计数随进程重启重置，崩溃/丢失提交回执可能漏计，不替代审计记录。隔离子进程内部文件/SQL、GPU 资源及首 Token 指标仍未覆盖；各耗时统计口径见 Server README。
- HTTP 自动生成 `X-Request-ID`，覆盖正常响应与错误响应，忽略客户端伪造值；CORS 显式暴露该响应头。迁移 0014 将原始 request_id 保存在任务记录中，旧记录可空；幂等重试仅产生新的访问 ID，不改变原任务关联或幂等摘要。工作流 JSON 不变。
- 原始请求 ID 显式传到线程、隔离进程、并发代码、async 引擎和 Redis Worker；动态合批逐项携带 ID，批处理方法自身无唯一请求上下文。上下文在执行结束后复位，代码直接调用无伪造 HTTP ID。任务查询可在 Server 重启后恢复原始关联。
- 元数据 JSON 事件覆盖 HTTP、任务选择、Worker 调用和已确认终态，关联 request_id/task_id/入口/Worker PID；进程重建后的完成日志更新 PID。默认启动关闭原始 Uvicorn 访问日志，编辑器轮转日志支持事件 JSON 格式。事件不含正文、原始 URL、凭据、身份或异常文本；HTTP 持久审计另行实现，WebSocket 请求关联和完整部署日志安全仍未覆盖。

- 编辑器历史日志最多 64 个任务、每任务 200 行、总文本 4 MiB，WebSocket 最多 128 个待发送操作，每次等待 1 秒；关闭取消待发送任务。日志消费错误不写回自身日志通道，避免递归。编辑器可观测丢失增加无身份标签的计数指标。
- 默认管道/终端控制台写入使用独立有界队列及非缓冲重复描述符，慢控制台不占用 HTTP 事件循环；关闭最多等待 250 ms，未完成写线程可能保留至输出恢复或进程退出。普通文件仍同步写入，避免 Uvicorn 重新触发 SIGTERM 前丢失最终生命周期消息；日志文件 10 MiB 轮转、保留 5 个备份。编辑器先配置 HTTP 日志再创建自身处理器，避免 dictConfig 关闭已在使用的处理器。
- 未覆盖的日志边界包括无字段标识的秘密、自定义处理器、主进程直接写标准流、捕获初始化前的库输出、跨独立记录的秘密、文件系统阻塞、长期重复重配时阻塞输出线程回收，以及 API-only/隔离进程丢失计数汇总；日志不是审计账本。

- 编辑器终态历史增加已有展示内容的持久预览：String/Bool/Num 的 JSON 安全值在 Worker IPC 前提取，和任务终态写入同一历史记录，复用原 DB JSON 列，无迁移。状态查询与 WebSocket 完成消息返回相同 outputs/outputs_truncated，页面刷新、断连及 Server 重启后可恢复正在观察任务的预览，不重跑 Graph。另一不可序列化原生对象不再连带丢失文本。预览有节点/条数/UTF-8 字节上限，截断明确提示，非任意原生对象持久化。
- 真实浏览器验收修复了 Webui 输出节点无 param_ 时空对象访问导致白屏；布尔输出 False 也改为按值解释，不再把非空字符串当作 true。已确认完成后 sessionStorage 仍清理当前任务，因此再次刷新不会自动重新选择上一条完成任务，但持久预览可按任务 ID 查询。文件副本按下述实现保留；完整原生输出、历史自动选择与清理仍需继续实现；手动历史选取见下述 Log → History。

## API key 配置

API-only 启动时可传 `--auth-config auth.json`，Python 使用 `Server(auth_config=...)`。例如：

```json
{
  "keys": [
    {
      "subject": "image-client",
      "token_env": "NNDEPLOY_IMAGE_API_KEY",
      "entries": ["image"],
      "permissions": ["deploy", "tasks:read", "tasks:cancel", "files:read", "files:write"]
    }
  ]
}
```

令牌从指定环境变量读取，至少 32 个字符，使用随机生成的值。调用发送 `Authorization: Bearer <token>`。未配置身份时保留本地匿名使用方式；配置后缺少或错误令牌返回 401，权限不足返回 403，其他调用者的文件和任务返回 404。管理令牌与调用令牌分别配置，管理令牌可检查所有记录；调用者只能将自己的文件用作任务输入。

需要对接现有身份系统时，通过 `app.dependency_overrides[current_identity]` 返回经过验证的 `Identity`；不能直接信任客户端传入的用户 ID。`get_server`、`get_db`、`get_storage` 提供公共依赖，数据库权限和引用检查仍在事务中执行。

也可自行提供临时数据库 URL，通过 `NNDEPLOY_TEST_DATABASE_URLS` 的 JSON 数组运行 `test/server/test_db.py`。请使用专门的测试数据库，测试会写入记录。

对象存储实现参考了 [OSS Python SDK V2 上传接口](https://www.alibabacloud.com/help/en/oss/developer-reference/simple-upload-using-oss-sdk-for-python-v2)、[COS Python SDK 常见问题](https://cloud.tencent.com/document/faq/436/56531) 和 [OBS Python SDK 指南](https://support.huaweicloud.com/intl/en-us/sdk-python-devg-obs/obs-sdk-python-devg-pdf.pdf)，并对本机已安装 SDK 的接口进行了检查。

数据库连接等待实现核对了 [PyMySQL 连接参数](https://pymysql.readthedocs.io/en/latest/modules/connections.html)、[Psycopg 3.2.0 等待生成器](https://github.com/psycopg/psycopg/blob/3.2.0/psycopg/psycopg/waiting.py) 和 [Psycopg 3.2.0 连接生命周期](https://github.com/psycopg/psycopg/blob/3.2.0/psycopg/psycopg/connection.py)，并在已安装 3.3.8 binary 与临时 3.2.0 pure-Python 环境执行实际数据库测试。


编辑器历史保留默认关闭。可用 `--editor-history-retention-seconds 86400` 或 `Server(..., editor_history_retention_seconds=86400)` 启用，最短 60 秒。现有维护循环每轮最多清理 100 条超期终态历史；管理接口 `POST /api/queue/history/cleanup` 可立即执行同一策略，未配置时不删除。时间以数据库时钟为准。清理在一个事务中删除完整历史/请求正文、解除输出文件引用并标记内容待回收；实际文件由原文件清理流程删除，正在进行的下载受读取引用保护。待处理及运行中任务不参与清理。

清理后保留原任务 ID、请求 SHA-256 与最小终态摘要，沿用原任务表 JSON，不增加配置文件、公共实体或数据库迁移。同一正文和 ID 重试仍返回原任务，不重新入队；正文变化返回 409。按 ID 查询仍返回原成功/失败/取消状态及 `outputs_expired=true`、空输出；History 列表不再显示已清理项，失效的翻页游标需返回 Latest。旧终态记录和更早仅有历史的记录在清理时转换，提交回执丢失或晚到的完成重试不会复活已清理结果。跨实例查询和维护会失效本地原生缓存。前端结束等待并在 Webui/当前 Log 持续说明结果过期。摘要当前无限期保留以阻止旧 ID 再次执行，数量有界的摘要/退出归属清理仍待独立设计；不能把本功能称为全部任务元数据都已回收。同工作区任一启用策略的实例都可清理该工作区历史。
