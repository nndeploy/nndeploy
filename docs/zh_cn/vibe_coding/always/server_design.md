**1. 目标与约束**

在现有 `python/nndeploy/server` 上形成完整的 AI HTTP Server。工作流编辑器、工作流 JSON、代码构建的 Graph、普通 Python 算法都使用同一套 Server、任务、Worker、文件和数据库能力。

统一约束：

- 公共模块仅使用 `nndeploy.server`，公共入口为 `Server`。不增加平行的入口包或公共执行框架。
- 对外计算调用使用 Deploy；启动、停止和重载使用 Start、Stop、Reload。
- 保留现有 Workflow、Graph、Node、Edge、Worker、Task、File。运行名称是 HTTP 路由键，不再形成一套发布业务对象。
- 不引入需要用户操作的 Artifact、Revision、Deployment、Alias、Contract。内部锁、校验摘要、文件引用和执行序号仍按正确性需要实现。
- 原始 `workflow.json` 的格式保持不变。附加配置采用 `workflow.server.json`；其他文件名使用 `<工作流文件名去掉扩展名>.server.json`，也允许显式指定路径。
- 算法专用代码留在算法目录下的 `server/`，公共设施留在 `nndeploy.server`。
- 完整功能通过少量公共入口使用；内部文件拆分依据职责，不要求用户创建内部组件。
- 默认 SQLite、本地文件、每入口的本地队列即可运行。MySQL、PostgreSQL、对象存储、Redis 按配置启用。
- 工作流和代码接入不因数据库、存储后端改变而修改计算逻辑。
- TaskQueue 共用实现，按对外入口隔离队列；模型之间默认不因同处一台机器或同一 Server 而串行。全局限额是总量约束，不是一条机器级 FIFO 队列。

完整范围包括单机和多个 Server/Worker 实例的显式部署。自动扩缩容、跨地域调度、任意代码热替换、通用 GPU 算子级抢占不属于本次范围。多实例能力不等于这些能力已经具备。

**2. 当前代码基础与实际差距**

| 现有代码 | 当前基础 | 必须改造的内容 |
| --- | --- | --- |
| `server/server.py` | FastAPI、工作流 CRUD、模板、文件、WebSocket | 拆开应用装配和编辑器功能；挂载 Deploy 和管理接口；避免全局单例影响多实例 |
| `server/app.py` | CLI、Worker 启动、监督、调度与结果线程 | 增加 API-only 启动；统一退出和恢复；按需加载编辑器依赖 |
| `server/task_queue.py` | 优先级、任务状态、取消、有限内存历史 | 容量限制、等待结果、期限、持久化；移除对具体 Server 对象的直接回调依赖 |
| `server/worker.py` | 子进程执行、进度、取消、插件加载 | 常驻 Graph、固定执行线程、队列路由、多 Worker 和异常恢复 |
| `server/executor.py` | 调用 GraphRunner、资源下载处理 | 支持 Graph 与 Python 入口；加载、执行和释放分开；可选依赖延迟导入 |
| `dag/graph_runner.py` | 工作流加载、运行、同步、释放 | 当前每次调用初始化和释放，需要补充常驻生命周期；旧 `run()` 保持兼容 |
| `server/task_bus.py` | 代码中已有增量事件回调基础 | 核对 Worker 到 HTTP 的完整接线，统一事件格式和背压；不能视为完整流式支持 |
| `server/files.py` | 本地上传、浏览、删除等 | 内容读写抽离到 Storage；增加访问范围、请求目录、过期清理 |
| `server/db.py` | sqlite3、工作流与模板 | 可迁移的表结构、连接/事务管理、多数据库、任务和文件记录 |
| `server/__init__.py` | 导入 CLI 和清理入口 | 导出明确的 Server API；避免导入即触发 CLI、日志或编辑器初始化 |

`server/graph_runner.py` 中的历史注释实现不作为另一套执行器。计算逻辑继续以 `dag/graph_runner.py` 为准。

此前撤销实现中已有测试覆盖的隔离、背压、失败重建、安全重载和文件清理行为，应迁移到新的公开入口测试中。只保留与本方案行为相符的实现，不整包恢复旧架构。

旧编辑器一次性 Run 的兼容路径也必须纳入应用生命周期：监督线程持有替换后的 Worker，重启等待可取消，启动失败和正常 SIGTERM 都回收辅助线程与子进程。内部通信不能依赖被强杀 Worker 持有的共享锁；失联读取不能吞掉后续请求。当前使用本地 manager 持有队列，并在执行前确认接收，只归还未确认接收的任务；这些都是内部实现，不增加用户配置或公开对象。同一编辑器主进程内，已确认接收的任务在 Worker 确认退出后按失败或已有取消意图结束；已交给 manager 的结果在主进程通知丢失时仍可回收。任务取消与派发协调，运行中取消必须等实际计算返回或进程退出，清空队列保留已确认接收的执行。manager 自身退出时暂停旧 Run 接收，就绪返回 503；确认旧 Worker 退出后，将已派发及派发中的不确定任务按失败或取消结束，不自动重算。父进程未派发堆和既有历史保留，队列与 Worker 重建就绪后继续处理；替代启动失败重试，关闭等待并回收创建中的子进程。尚未转交父进程的 manager 结果会丢失。调度、结果收集、进度、Worker 监督和日志线程异常退出时也执行上述暂停及恢复；已知结果写入 DB 失败时保留存活 manager 并重试，全部写入后才更换队列。主进程有界队列 RPC 超过内部期限时，由不获取队列/日志锁的检测线程终止对应 manager，解除 IPC 等待后走同一恢复流程；合法队列等待及 Graph 执行不按该期限误判，关闭期间检测仍持续。manager 启动握手和代理创建共用内部创建期限，超时明确失败并回收未完成初始化的子进程；关闭握手也有期限，运行中重建失败重试，关闭意图停止重试。非 IPC 本地线程及数据库非 I/O 阻塞、整机重启、异主机及未知退出证据的恢复仍需完成；旧 Run 的终态历史接口元数据已按工作区写入公共 DB，跨 Server 重建可查；旧 Run 接收、可能派发和取消意图也已持久化；同工作区同次系统启动内，须确认 Server 和实际 Worker 全部释放退出证明后，才继续未派发任务，或将不确定执行记为失败/取消且不重算。原生结果对象和输出资源的持久保留仍需完善。子进程观察原父进程 sentinel，在 Python 观察线程能够运行时退出，不将其等同于任意原生调用的硬退出保证，也不将“新 Worker 已启动”视为完整故障恢复。

插件文件仍放在现有资源目录。上传先写临时文件，写完后原子替换；通知只作提示，使用容量为 1 的队列合并积压。Worker 每次执行前扫描目录并统一导入，通知丢失或 IPC 重建不影响已保存的新插件发现。兼容旧式外部路径通知时每次最多取 64 条，防止持续上传推迟 Graph 执行；该上限不保证文件系统或任意插件代码的执行期限。上传请求取消后等待其文件写入退出再关闭输入流；已有同名插件不自动热替换。

**4. 总体架构与依赖方向**

```text
编辑器 / 工作流 JSON / Graph / Python 代码 / 外部客户端
                         │
             Server（HTTP、校验、鉴权、按名称路由）
                         │
            ┌────────────┼────────────────┐
            ▼            ▼                ▼
         Queue A      Queue B          Queue C
            │            │                │
       Worker A     Worker B1/B2      Worker C
            │            │                │
         模型 A       工作流 B        算法自身调度
            │            │                │
            └────────────┼────────────────┘
                    结果、文件、事件

共享实现和设施：TaskQueue / DB / Storage / Redis / 日志 / 指标
资源限额：应用/入口/设备级准入；不默认建立整机串行执行队列
```

Server 负责请求、任务和资源；DAG 负责计算。`dag` 不依赖 FastAPI、数据库、Redis、用户身份或云厂商 SDK。

将现有 `NnDeployServer` 改造为可代码创建的 `Server`，旧名称和 CLI 保留兼容入口，不再增加套在它外面的完整 Server 实现。共享依赖保存在应用实例状态，通过 `dependencies.py` 获取，避免跨应用共享全局实例。

公共操作限定为添加执行入口、启动、停止、重载、查询、Deploy。注册表只是“名称 → 创建代码及能力说明”的映射，不记录发布历史。

一个 Server HTTP 应用可以有多个命名入口，每个入口关联工作流、Graph 或代码。隔离单位是这个入口，不是 Graph 中的每个模型节点；一个包含多个模型的 Graph 仍由 DAG 编排为一次任务。名称直接对应路由中的 `{name}`，不另外维护可变别名。编辑器默认使用工作流 ID 作为稳定名称，展示名称继续使用工作流名称；自定义名称必须在 Server 范围内唯一，冲突返回 409。

**5. 三种运行方式**

| 方式 | 行为 | 适用范围 |
| --- | --- | --- |
| 带编辑器的 Server | 同一应用挂载编辑器、工作流管理和 Deploy 路由 | 本地搭建、调试和小规模使用 |
| API-only Server | 启动同一套执行能力，仅挂载调用及授权管理接口 | 独立运行、生产部署 |
| 多实例 Server + Worker | 关系数据库、共享对象存储和 Redis 配合 | 多进程、多节点的显式部署 |

关闭带编辑器的整个 Server 会停止它拥有的 Worker。若需要关闭编辑器后台后仍可调用，使用单独启动的 API-only Server；编辑器通过受保护的管理接口提交已有工作流和配置。此时只有进程通信，不增加发布对象。

独立模式不依赖编辑器数据库中的 ID：它接受实际的工作流内容或受信任资源引用。编辑器 ID 只用于关联来源。跨主机启动时由现有文件接口上传缺失资源或引用共享 Storage，Server 取得本地可用文件后再加载；不能把编辑器机器的路径原样发给另一台机器使用。

多实例只支持具有共享语义的数据库和资源位置。不同机器不能把同一个本地绝对路径当作同一资源。SQLite + 本地目录的默认模式不宣称支持分布式 Worker。

同一机器运行多个模型时，分别处理以下情况：

| 场景 | 排队与执行归属 | 并行语义 |
| --- | --- | --- |
| 多个独立 Server 进程、不同端口 | 各进程独立队列及 Worker，默认独立运行目录 | 可以同时执行；不会自动发现彼此并排成一条队列 |
| 一个 Server 托管多个命名入口 | 每个入口独立队列，默认独立 Worker 或独立执行线程 | A 的长任务不阻止 B 派发；实际速度取决于硬件和算法 |
| 多个请求调用同一普通 Graph | 同一入口内排队，一个 Graph 实例默认一次一个请求 | 可用多个独立 Graph Worker 提高并行能力 |
| 入口使用支持多请求的算法引擎 | 外层限定在途数量，交给引擎自身调度 | 引擎可以执行连续批处理或 Token 级调度 |
| 多个 Server 显式组成同一组 | 使用相同的共享配置、DB/Storage 和 Redis 命名空间 | 同一入口的 Worker 消费该入口队列，不同入口保持隔离 |

只使用相同 Redis 地址或数据库地址不应意外合并任务域。独立部署需要不同命名空间和配置范围；同组部署需要明确一致的入口名称、权限与配置。共用数据库/schema 时持久化记录按配置范围隔离，文件对象前缀和 Redis key 使用相同范围。多个独立进程不能无保护地共享同一个本地运行目录。


**6. Python 接口与对象所有权**

以下为拟议接口。

```python
from nndeploy.server import Server

# 工作流文件
server = Server(workflow="workflow.json", config="workflow.server.json")
server.run(host="127.0.0.1", port=8000)
```

```python
# 已构建的、尚未初始化的 Graph；使用当前进程内的受控执行线程
server = Server(graph=graph, name="detect")
server.run(port=8000)
```

```python
# 原生进程隔离、多 Worker：在各 Worker 内创建 Graph
server = Server(graph_factory=build_graph, name="detect", workers=2)
server.run(port=8000)
```

```python
# 无状态函数
server = Server(deploy=my_deploy, name="detect",
                input_model=DetectRequest, output_model=DetectResponse)
server.run(port=8000)
```

```python
# 常驻模型，不要求继承框架基类
class TextDeploy:
    def init(self):
        self.model = load_model()

    def deploy(self, inputs):
        return {"text": self.model.generate(inputs["prompt"])}

    def deinit(self):
        self.model.close()

server = Server(handler_factory=TextDeploy, name="text",
                input_model=TextRequest, output_model=TextResponse)
server.run(port=8000)
```

单个 Server 托管多个模型的拟议代码：

```python
server = Server()
server.add(name="detect", graph_factory=build_detect_graph,
           config="detect.server.json")
server.add(name="ocr", graph_factory=build_ocr_graph,
           config="ocr.server.json")
server.add(name="chat", handler_factory=build_chat_handler,
           config="chat.server.json")
server.run(port=8000)
```

上述入口拥有各自的队列和运行参数。多个入口使用同一实例的 `add(name=..., workflow=.../graph_factory=.../deploy=...)`。`create_app()` 返回可挂载的 ASGI 应用，`run()` 负责独立启动。入口参数互斥，不能同时传入 workflow、graph 和 deploy。

所有权规则：

- 传入未初始化 Graph 后，其执行期间的初始化、运行和释放由 Server 独占管理，调用方不再并发操作它。
- 不静默迁移已经初始化的 Graph；首先拒绝并给出明确说明，或仅在后续实现验证过的显式接管方式下支持。
- 直接 Graph 对象或捕获不可序列化对象的函数不自动具备多进程能力。工厂函数/可导入入口用于进程隔离。
- 同步函数进入执行线程，异步函数使用所属 Worker 的事件循环；生成器和异步生成器按流式入口处理。
- 创建、初始化、执行、同步和释放保持资源所需的线程/进程归属。构造函数已创建 GPU 上下文的代码优先采用 Worker 内工厂。
- Python 调用通常在启动时固定；热重载 Python 模块通过重启对应 Worker 实现，不在正在执行的对象上替换类定义。
- 代码接口的 schema 由显式 Pydantic 模型或受支持的类型标注生成。无法推导时要求声明，不能猜测任意 Python 对象的结构。

**7. 编辑器操作与工作流接入**

界面入口为 `Server`，所有新增文案为英文。常用视图只展示 Inputs、Outputs、Parameters、Status、Endpoint、Start/Stop/Reload 和调用示例；高级配置折叠。

Start 的一次操作执行：

1. 使用现有保存逻辑保存画布；模板保存为用户工作流。
2. 取得这一次保存的确切内容，不在异步过程中反复读取可能被其他页面修改的文件。
3. 加载已有 `workflow.server.json`，或识别已知节点/公开端口并生成默认配置。
4. 检查配置、插件和资源；类型或映射有歧义时在页面指出具体节点/字段。
5. 准备当前运行所需的配置和资源，交给 Worker 初始化。
6. 只有初始化、绑定和配置的预热全部成功后才显示 Ready 和调用地址。

普通保存不修改在线 Graph；Reload 显式应用当前画布。页面自动显示当前入口，无需选择部署记录。调用示例始终来自正在运行的配置，不能被未启动的草稿改写。

后台在一次 Start/Reload 中完成校验和配置保存，不要求浏览器先调用多个检查/保存接口。HTTP 响应丢失时，浏览器保留操作标识并重试。编辑器用现有工作流的修改校验值检查并发编辑，冲突返回 409；校验值是内部一致性数据，不显示给用户管理。

原有 Run 仍执行一次性工作流，不自动变成常驻调用。Graph 内部并行配置保持原意：只有验证可重复、安全隔离的执行类型才开放给常驻 HTTP；不把所有 Graph 静默改成串行，也不宣称任意流水线都已支持。

**8. 配置格式与输入输出转换**

区分应用配置和工作流配置：`server.json` 控制 HTTP、DB、Storage、Redis、鉴权等环境设施；`workflow.server.json` 控制当前入口的输入输出、运行和资源策略。数据库和云凭据不进入工作流配置。

最小工作流配置：

```json
{
  "name": "image-copy",
  "inputs": {
    "image": {"node": ["decode"], "type": "image"}
  },
  "outputs": {
    "image": {"node": ["encode"], "type": "image"}
  }
}
```

映射规则：

- `node: ["subgraph", "decode"]` 使用真实节点路径，避免拼接字符串产生歧义。
- `edge: "image"` 引用 Graph 已公开的输入/输出边。内部边不能未经检查就当成外部端口。
- 已知输入输出节点由内部转换实现读写；配置不要求填写适配器名称。
- 多输入/多输出节点可用 `port` 指定端口；无法唯一识别时必须显式指定。
- `type` 描述 HTTP 数据类型，不替代节点的设备、布局、dtype 等计算类型信息。数组/Tensor 转换额外声明 dtype、shape/大小上限，校验后再分配内存。
- 参数可声明节点路径、已支持的参数名、类型、范围、required 和 default；不允许任意 setattr 或请求期间重新反序列化整个 Graph。
- 只有明确支持运行时修改的参数可以按请求变更；设备、权重和初始化参数通过 Reload 生效。
- 可选字段必须有明确定义的默认值，包括显式 null；每次请求应用默认值，不能继承上次请求。
- 拒绝未知字段、重复 JSON key、重复写入目标、非法类型和无法安全序列化的结果。
- 不明确公开的参数不允许客户端修改。对外 Deploy 请求不接受任意工作流或 Python 导入路径。

算法特定的预处理/后处理留在算法目录；通用 Base64、MIME、JSON、文件引用、图片/音频编码等放在 Server 的 `io.py` 和 `media.py`。

当前 Graph 文件转换复用现有端口：image 字段支持 PIL Image 与 OpenCV/NumPy 图片，file 字段支持 bytes 输入输出，以及 str/InputStr 的受管理输入路径。可选 media_type 约束具体 MIME，不改变工作流 JSON；输出在请求临时目录内按声明格式生成，内容校验通过后发布到原文件接口。默认图片输出 PNG、普通字节输出 octet-stream；返回已有文件引用的代码入口也核对最终 MIME。图片像素、文件字节及 ffprobe 音视频时长/容器/尺寸限制均生效。自动识别已知标量、PIL 与 bytes 公共端口，未知数组布局仍需明确配置。整份音视频文件的 bytes/path 转换不等于原生视频节点的逐帧常驻循环、音频采样/布局转换或具体模型协议；各自实现及验收范围见下述约定。

原生 OpenCV 图像/视频节点的常驻适配现已单独实现并完成本地专项验收：一个视频解码输入、视频编码输出的顺序 Graph 逐帧执行，每次请求复位编解码资源，算法节点继续常驻。沿用原节点配置，运行副本保护已绑定 codec 的草稿路径，原工作流 JSON 不改写；输出视频画面不混入原音轨。限制及三数据库/共享 Worker、真实 HTTP 验证见实施记录。音频数值端口转换已接入，见下述约定；其他媒体组合仍须分别验收。

当前数值转换使用 `type: "array"`（代码 NumPy）或 `type: "tensor"`（原生 nndeploy Tensor），必须声明 `dtype` 和 `shape`。例如 `{"type":"tensor","edge":"input","dtype":"float32","shape":[null,2],"max_elements":4096,"max_bytes":16384}`；调用值为 `{"dtype":"float32","shape":[2,2],"data":[1,2,3,4]}`。平铺数据采用行优先顺序，shape 的 null 维度允许变化。Scalar 使用空 shape 和一项 data，零维度大小对应空 data；整数拒绝浮点/溢出，浮点拒绝非有限值和超范围值，minimum/maximum 作用于元素。

配置默认每字段最多 1,048,576 元素 / 8 MiB 数值存储，可显式设置，硬上限 16,777,216 元素 / 64 MiB；HTTP JSON 正文大小另行限制。输入验证后才分配 NumPy/原生 Tensor，输出在下一请求复用缓冲区前转成独立 JSON，再进入 Task、事件和幂等记录。MySQL 任务正文及结果使用 LONGTEXT，升级保留已有记录。现有标量字段的序列化保持不变，避免新增可选字段改变其共享队列配置摘要。

代码数组最多八维，支持 bool、int/uint 8/16/32/64 位及 float16/32/64；原生 Tensor 遵循现有转换器，支持数值类型和最多五维。可信输入字段的 `device` 可选择已编译可用设备，默认为 CPU，HTTP 数据不能覆盖设备选择；输出先检查元数据及实际存储大小再下载到主机。真实 GPU 需单独验收。数组文件传输复用现有 media_type 和文件接口：array/tensor 字段声明 application/x-npy 后，输入和输出使用 {file_id}，算法仍读写原生数值；没有新的上传、发布或资源类型。NPY v1/v2 支持现有数值 dtype、大小端和 C/Fortran 布局，Worker 获取独立的本机字节序数组。文件头最多 10000 字节，读取前检查长度；拒绝 pickle/object、结构化类型、复数、非有限数值、超限维度/元素/字节、截断和尾部附加数据。字段形状、类型及元素范围在任务准入前和执行时重复检查。输出沿用 Task 身份、attempt、worker_token、文件保留和对象存储；预热只校验结果，不发布持久输出。引擎第一次让出事件循环前将输出复制为独立二进制，再在线程完成文件操作；取消须等待文件操作实际结束。Tensor 文件采用配置格式，不能在 file_id 请求内覆盖；输出依原生实际格式转换后写入。文件容量还包括 NPY 头部，字段 max_bytes 仅限制数值数据。未声明该 MIME 时继续使用 JSON；使用 64 位整数的 JSON 客户端需保留整数精度。

Tensor 字段可选 `data_format` 使用原有原生格式名：N、NC、NCL、S1D、NCHW、NHWC、OIHW、NCDHW、NDHWC、NDCHW；配置 shape 表示算法接收的目标格式，S1D 的第二维固定为 1。请求仍使用 dtype/shape/data，可额外携带源 data_format，省略时表示与配置相同；仅允许相同命名轴之间换轴。校验变换后的形状、元素和字节上限后，Worker 将数据重排并创建目标格式 Tensor，不只修改标签。输出读取实际 Tensor 格式并转换到声明格式，保存带 data_format 的独立 JSON。输出字典也遵循相同变换；OIHW 不可当作 NCHW，Auto 及 NC4HW/NC8HW 等打包格式不支持，未声明格式的原接口保持不变。转换复用代码、Graph、预热、流式和批处理的数组实现，不更改工作流或模型节点参数。CPU 已有本地验收，GPU 仍须在真实设备验证。

Graph 使用实际节点端口类型核对绑定。明确声明 numpy.ndarray 的 Python 端口及显式 set_type(np.ndarray) 的 Edge 保留原数组和 Python 所有权，支持标量到八维数值数组及字段允许的全部 dtype，不经过 OpenCV 强制转换；只读、步长和单通道维度保留。队列阻塞前保留声明类型，后续请求发布不会丢失类型。连接原生 cv::Mat 的边仍走图像路径，限定二维或 HWC 和相应 dtype；HWC 要求 2–512 固定通道，单通道使用二维形状。不兼容声明在启动时拒绝，未声明类型的独立 Edge 保持旧图像语义。原生模型 Tensor 使用 tensor 字段；跨请求输出在进入 Task 前转换为独立 JSON 或受管理的 NPY 文件，不让模型复用缓冲区修改历史结果。

可选运行配置示例：

```json
{
  "name": "image-copy",
  "inputs": {"image": {"node": ["decode"], "type": "image"}},
  "outputs": {"image": {"node": ["encode"], "type": "image"}},
  "execution": {
    "workers": 1,
    "devices": ["cpu"],
    "scheduling": "serial",
    "max_concurrency_per_worker": 1,
    "max_queue_size": 32,
    "queue_timeout_seconds": 30,
    "execution_timeout_seconds": null,
    "http_wait_timeout_seconds": 60,
    "restore_on_restart": true
  },
  "resources": {"mode": "managed"}
}
```

其中 workers、设备范围、队列容量、并发和期限均属于该入口，不是整台机器的设置。普通 Graph 默认 serial；concurrent 只用于声明可并发且通过验证的代码；engine 表示请求交给算法自身调度，外层仍执行校验和在途数量限制。配置与算法能力不相容时启动失败，不静默改变并发方式。

异步 engine 接口的 `deploy` 使用 async 函数或 async 生成器，同一个 Worker 的 factory/init/deploy/deinit 在所属事件循环线程执行。`max_concurrency_per_worker` 控制每个引擎对象的在途请求，`workers` 仍表示独立引擎对象数量。算法适配代码必须等待实际计算结束，不能在原计算仍运行时就返回结果或取消确认。`execution.cooperative_cancel=true` 是算法对取消安全性的显式声明：协程取消应等待对应计算与清理结束，才可释放名额；默认不作此假设。协作取消不是原生计算硬抢占，硬终止仍需隔离进程。任务上下文在并发请求间隔离，不能使用进程全局回退值传递当前任务身份。

任务消费者的等待与实际执行由 Server 分别持有，取消内部等待者不能丢失已经发出的 DB 事务或实际计算。消费者意外结束时，仅使所属入口拒绝新请求；Stop/关闭仍收集所有消费者结果、等待全部 Worker 退出，再恢复已持久化结果或结束本实例归属的未知任务，最后释放文件与设备引用。任何未确认的物理退出或持久化结果都不能伪装成成功清理，也不能影响其他实例的任务。算法自身的 `CancelledError` 在实际计算边界转换为任务取消，保留可复用 Worker 和合批调度；异常控制流不允许由收尾逻辑产生空的成功结果。

`devices` 是 Worker 允许使用的设备范围。实际 Graph/代码的设备配置必须与其一致，不能仅标注一个设备名就认定模型已迁移。多 Worker 的放置由显式参数或已声明的工厂能力决定；多卡模型由工厂声明完整设备组，Server 不把它拆成单卡实例。无法验证设备归属的自定义代码不能获得严格设备隔离承诺。

应用级配置示例，所有字段均为拟议格式：

```json
{
  "http": {"host": "127.0.0.1", "port": 8000, "editor": true},
  "database": {"url": "sqlite:///./resources/db/nndeploy.db"},
  "storage": {"backend": "local", "root": "./resources/files"},
  "redis": null,
  "limits": {
    "scope": "server",
    "max_pending_tasks": 256,
    "max_inflight_tasks": 8
  },
  "entries": {
    "detect": {"workflow": "detect.json", "config": "detect.server.json"},
    "ocr": {"workflow": "ocr.json", "config": "ocr.server.json"}
  }
}
```

应用级上限限制总量，不改变每个入口独立排队的结构。每入口和总量限额取同时满足的结果。多个进程若要共享总量限额，必须显式选择共享范围并使用跨进程协调；不能假定各自设置 8 就等价于整机最多 8。

应用配置优先级统一为：显式 Python 参数或 CLI > 环境变量 > 指定应用配置文件 > 默认值；工作流字段的显式覆盖同样校验并记录有效配置。秘密值不在有效配置查询和日志中原样返回。引用路径相对于配置所属目录解析，再接受资源根目录和权限校验。

**9. 执行、调度与任务语义**

对同步、异步和流式请求采用同一个 Task。已经接受的计算统一使用 `task_id` 关联结果、事件、文件和日志，不另建一套同义请求记录。HTTP 尝试可有 request_id 用于拒绝请求和传输诊断；它不成为另一套业务实体。对 API 暴露的小写状态与现有队列枚举建立显式映射，旧 `/api/queue` 响应保持原样。

任务状态沿用现有含义并补齐：pending、dispatched、running、succeeded、failed、cancelled、expired。取消请求先记录 cancel_requested，只有真正停止后才进入 cancelled。状态转换由条件更新保护，终态不能被迟到的进度覆盖。

排队和调度使用以下规则：

- 每个对外入口有独立的逻辑队列和执行名额。默认分配专属 Worker；直接 Graph 对象模式使用专属执行线程。同一入口多个 Worker 处理同一入口任务，不能误取其他模型的请求。
- 一个 Graph 实例默认串行执行请求。多个 Worker 创建独立实例，可能重复占用模型内存；扩大 Worker 数必须经过资源检查。
- 声明可并发的纯代码可以提高单 Worker 在途数量；依赖 Python CPU 密集代码的线程并发不承诺提高计算吞吐。
- LLM 等具有自身调度器的入口采用 engine 模式：外层负责校验、配额、任务记录和有界准入，把多个允许的请求交给引擎。不能设置一个等待前一请求完全结束的外层串行循环。
- 排队上限计入待派发及已派发未开始的任务，运行名额单独计数；不能转移到 multiprocessing.Queue 或引擎内部无界队列来绕过背压。引擎自身保留任务时必须提供容量或背压反馈。
- 一个入口队列满只拒绝该入口的新增请求；其他入口仍可接受任务，但仍受它们自己的限额和应用总量上限约束。若要求容量保证，可配置各入口的保留名额，避免一个入口用尽总量。
- 调度器只向有容量且设备匹配的 Worker 派发，不持有全局锁等待慢入口；共享资源时按公平策略选择可运行入口，优先级不得导致永久饥饿。
- Start/Stop/取消/心跳使用控制通道，不放在普通计算任务之后无限等待。重载、取消和故障恢复按入口作用域执行，不停止其他入口。

所谓全局限制必须注明范围：单个 Server 实例、显式组成的一组 Server，或同一主机上的指定设备。默认只提供实例及入口限额，不隐式控制其他独立进程。

设备资源规则：

1. 为 Worker 配置设备归属、CPU 线程限制、运行并发和可用时的内存预算。多个入口在同一 GPU 上可以同时运行，但速度、显存和引擎兼容性需要实际验证。
2. 模型加载和 Reload 先检查及预留资源；预热完成后保留必要运行余量。旧 Graph 在途任务未完成前，不把它的资源提前当作已释放。
3. 显存查询和配置预算只用于准入，不是硬件配额或确定性保证。非受管进程可能继续占用显存；OOM 必须按入口失败处理，不能声称已完全避免。
4. 独立 Server 若需同机协调，显式加入共享协调范围，设备键包含主机标识及稳定设备标识。控制范围仅覆盖参与者；不会自动控制机器上的其他进程。
5. 协调者失联或租约过期不代表原生计算结束，不得立刻释放执行名额并允许超额任务启动；先确认进程结束或将设备标为待核实。恢复后对账。
6. 默认不抢占、自动卸载或关闭其他入口以给新模型让路。资源不足返回明确错误；需要停机重载时由用户显式选择。
7. 共享 Worker 或 GPU 共享是显式优化，需说明故障及性能影响范围。请求与队列隔离不等于显存、算力或故障的物理隔离。

常驻模型预算的当前实现：应用通过 `device_limits` 配置每个设备的 max_workers 与可选 memory_bytes；入口使用 execution.devices 声明每 Worker 的完整设备组、execution.memory_bytes 声明每设备的常驻内存估计。申请按 Worker 数相乘，在单个数据库事务内同时检查全部设备，成功后才构造任何模型。Reload 在旧模型关闭前同时计入新旧占用，不足拒绝候选并保留原入口。默认按持久 Server 工作区协调；显式 host 作用域还要求 namespace、稳定 host_id、每设备稳定 physical identity 和共享数据库。独立工作区默认互不干预，设备别名不替代稳定物理 identity；存在占用时策略冲突拒绝生效。

迁移 0021 保存内部设备策略和常驻占用，旧版本模型不伪造占用归属；启用预算需要一致升级并重新登记模型。正常关闭确认全部 Worker 结束后释放；自动恢复使用控制进程及隔离子进程共同持有的 OS 退出证据，而非心跳/PID/租约到期。恢复可检查同主机其他可访问工作目录，但仍要求同次内核启动、原文件标识和完整锁证据，先撤销迟到子进程再删除占用。未确认记录不自动过期，单条失败不阻塞其他可确认的模型恢复。DB 回执丢失重试同一申请或释放。管理查询复用 `/api/server?include_resources=true`，不新增用户需管理的资源实体。

迁移 0022 进一步记录原 Task 对应的设备执行占用；不新增公开任务状态或用户管理对象。设备可声明 max_concurrency，普通 Deploy 一次调用占一个名额，动态合批的一次实际批计算也只占一个名额。多设备组原子获取全部名额，等待沿用现有任务队列容量和期限，完全不同设备可以独立前进。reserved_slots 按已有入口名保留不可借用的份额，总和不能超过并发上限；execution.priority 为 -10 到 10，每一点提前一秒排序，等待年龄阻止持续的新高优先级请求永久插队。排序只覆盖已进入设备等待的调用，入口内部调度保持原规则；重叠设备的较早等待者可以阻止较晚者，以避免多设备请求饥饿，入口自己的未用预留份额例外。

执行占用必须在 DB 中确认才进入计算，等待时复查取消、期限和 Task 归属。计算返回后释放；释放事务失败不改变已知计算结果，后台重试，完整运行归属确认退出后也可对账删除。运行占用不因超时或心跳过期而释放。管理查询返回设备执行 running/waiting 数量，按批调用而非批内 Task 计数。本地 pending 与 Redis 领取后 running 的既有状态约定保持不变。Start/Reload 的每个 Worker 初始化在工厂/Graph 加载前获取同一套执行名额，持有到全部预热结束；等待、加载、预热共用现有每 Worker 启动期限，不在获取名额后重置。多 Worker 仍逐个初始化。设备等待排序与保留份额沿用 Deploy 规则，不增加用户 Task 或公开状态，内部占用记录用初始化标记区分；管理 running/waiting 包含初始化占用。初始化异常若无法确认清理，不提前释放名额；确认全部 Worker 关闭或物理归属退出后回收。执行名额也覆盖整个 Deploy Worker 调用，包括调用内的隔离 Worker 重建。

迁移 0023 为既有占用增加临时内存及运行峰值字段，旧记录以零补齐并保留归属；MySQL 的设备与入口名统一精确比较，避免默认排序规则合并不同设备或入口。入口可使用 execution.temporary_memory_bytes 声明每请求预算，需要设备 memory_bytes 上限。初始化/预热及合批输入准备按一个请求计，实际批计算按有效成员数计；多设备额度和执行名额在同一事务获取。常驻内存加全部运行临时内存不得超过上限，独立配置内存上限也能排队。模型加载还为各 reserved_slots 留出对应最大批量峰值，并为其余入口留出最大的单次峰值；已有实际临时占用加未使用的保留内存同样参与加载检查，加载不能挤占既有入口的保留容量。最大批量无法容纳时拒绝加载，不自动缩小批量。其他入口不能借用保留内存；运行取消、超时和心跳过期不证明内存已经释放。沿用物理退出恢复、稳定申请标识及 DB 释放重试，不新增公共实体或任务状态。管理查询 memory 区分 resident_bytes、temporary_bytes、used_bytes、available_bytes、required_headroom_bytes；available_bytes 包括受保护余量，不等于任意入口可立即使用的额度。未声明的临时内存不参与计算；声明协调不代表实际分配器限制或真实显存测量。

可选 execution.cpu_threads 为隔离进程 Worker 设置受支持计算库的线程上限，默认省略，不增加配置文件或公开实体。普通线程模式拒绝设置，防止进程全局修改影响其他入口。Worker 在工厂前、工厂后及每次 Deploy 前刷新库设置，初始化/预热、崩溃重建、Reload 复用；Graph init 前递归调整已有后端线程参数（保留更小值），原 JSON 不变。threadpoolctl 处理支持的 BLAS/OpenMP，已加载的 OpenCV、NumExpr、PyTorch 使用各自接口；不额外加载模型框架。OpenCV GCD 不支持正数上限时改用串行，无法限制则启动失败；失败 Reload 保留旧 Worker。此项是各库的计算线程设置，不代表 OS 总线程配额、CPU affinity 或主机 CPU 总量；未识别库、自定义线程、算法自行重设及模块导入过程需要专属控制。当前实测覆盖 OpenCV GCD、原生参数和进程生命周期，其他库的线程限制效果仍待对应环境做功能验证；本轮不做性能测试。

旧编辑器 Run 也复用 `execution.cpu_threads`，要求 `isolation=process`，可通过已保存工作流的同名 `.server.json` 配置，是否启用设备预算均可。线程设置在插件加载前应用，Graph 初始化前递归设置后端参数，初始化完成后再次刷新计算库。配置线程数的 Run 完成或失败后退出该 Worker，下一次请求使用新进程，防止配置或插件全局状态影响后续工作流；父进程及其他模型入口不变。没有线程限制、执行期限或设备预算时，仍使用原 Worker 复用方式。

启用 device_limits 的编辑器 Run 复用同一预算：浏览器自动在原 POST /api/queue 中附带 workflow_id 查询参数，正文仍是原 Graph JSON。已保存工作流的同名 .server.json 提供 execution.devices、memory_bytes、temporary_memory_bytes、priority 和 queue_timeout_seconds；不增加文件或发布对象。模板需先保存为工作流并设置已有执行配置。缺少已保存工作流或配置、未知设备、缺必要内存声明，以及不适用一次性 Run 的多个 Worker/并发/合批设置会拒绝新请求。CPU 线程与执行期限也复用原 execution 设置，机制见下文。未提供附属执行配置且未启用预算的旧 Run 保持原执行方式。

资源配置只在首次接收时解析并随原 Task 持久保存；重复提交先核对工作流及 workflow_id，不重新读取已修改或删除的 .server.json。旧浏览器尚未确认的请求保留原来不带 workflow_id 的地址；新请求的 ID 与原 Graph 正文跨刷新保留。已经接收但没有资源声明的旧请求，在启用预算后不会绕过检查运行。这里的快照只用于执行资源，与 Deploy 的输入输出绑定无关。

受预算管理的 Run 在插件加载和 Graph 初始化前申请一个 Worker 的实例数及内存，按同一设备策略等待执行名额及临时内存。等待检查持久任务归属、取消意图和从提交起计算的排队期限；多设备申请、保留份额及优先级沿用现有调度。实例/内存预留不足会使 Task 失败，保留其他模型；不会自动卸载模型或伪造等待成功。已开始的初始化、计算、输出保存和结果传递都保留占用。该次 Worker 在结果交付后退出，再由监督确认物理退出并通过原退出证据回收；正常退出自动补充 Worker，不显示崩溃提示。取消请求和 Task 终态本身都不是释放资源的证明。数据库回执丢失用原内部申请标识重试；物理退出后扫描回绕在同一次有界恢复中完成，避免因空扫描延迟排队调用。正常关闭及 IPC 重建同样只在 Worker 已退出后尝试回收。

编辑器 Run 也可使用已有 execution_timeout_seconds，无需启用设备预算；在同名 .server.json 中设置 execution.isolation 为 process，并配置执行秒数。例如：

```json
{"execution":{"isolation":"process","execution_timeout_seconds":30,"queue_timeout_seconds":60}}
```

附属设置在首次接收时随原 Task 固定。queue_timeout_seconds 从提交时间计算，已过期任务在 Graph 初始化前拒绝；execution_timeout_seconds 在取得设备名额后、加载插件和 Graph 前开始，覆盖初始化、计算、deinit、输出保存及结果交付。设备等待不消耗执行期限。没有附属设置且未启用预算时继续原 Run；有附属设置但未配置执行期限/预算时继续复用旧 Worker，不因本功能强制每次重启。

期限由原队列进程用单调时钟记录，父进程约每秒检查并终止到期 Worker；不依赖被原生调用占住 GIL 的子进程计时线程。接收结果时也检查期限，迟到结果不能覆盖终态。确认进程退出后才沿用原失败或取消状态、清理失败输出并释放设备占用。正常/到期受控退出自动补充 Worker，不提示异常崩溃。结果若已在期限内被确认接收，后续进程收尾卡住仍会在期限后被终止，但已确认结果与文件保持成功，不自动重算。

该期限不是硬实时响应承诺：检查周期、进程调度、IPC 和 OS 不可中断 I/O 仍会影响实际停止时刻；队列进程失联使用已有 IPC 故障恢复，数据库接收/结果落库与 HTTP 等待也有各自的期限。普通 Stop 仍沿用已有取消意图与 Graph 协作停止；配置的执行期限提供强制退出上限。当前真实原生阻塞验证在 macOS 完成，Windows 尚未验收。

同 Server 默认共享该实例预算；不同 Server 只有显式配置相同 host 范围、host_id、设备 identity 与数据库才协调。不改变 Graph 设备放置，不承诺真实显存测量、GPU 硬隔离或跨主机/整机重启恢复；未参与协调的进程仍在预算之外。已确认机制依赖同次系统启动内可验证的本地退出证据；缺少该证明的平台在接收前返回 422 editor_device_platform_unsupported，Worker 同时复查，避免留下无法回收的占用。Windows 的这一路径仍需实现和验收。

当前仍未完成非隔离模式及其他计算库的 CPU 线程控制、Graph/代码实际设备核验或显存查询。旧编辑器一次性 Run 按下述方式接入预算，非参与进程仍在预算之外；设备声明不会自动改变算法放置。真实 GPU、跨主机/整机重启/Windows 恢复仍需对应实现和环境验收，不能以 CPU 占用测试宣称 R27/Q08/Q10–Q12 全部完成。

显式批量调用定义逐条结果和整体错误。动态合批仅对声明能力的同一入口启用，按形状/参数兼容分组，遵守最大批量和最大等待时间，拆分结果保留原 task_id。不同模型、不同配置或不兼容身份隔离要求的请求不混成一批。算法自身已进行批处理时，外层默认不再次动态合批。

动态合批使用 `execution.batching={"enabled":true,"max_size":8,"max_wait_ms":5}` 显式开启。算法 handler 必须提供同步 `batch_key(inputs, **parameters)` 与 `deploy_batch(items)`：前者声明形状等兼容条件，后者接收带有 task_id、inputs、parameters 的条目列表，按相同顺序返回等长结果列表；可在列表中返回 ServerError 表示单条失败。Server 自动把调用身份和完整参数加入分组键，算法不能绕过它们混批。算法自行保证分组键足以描述模型输入兼容性。

每个 Worker 使用一个所属线程完成初始化、分组键计算、批处理和释放，最多保留 max_size 个在途条目，入口总容量为 max_queue_size + workers × max_size。优先调度最早到达的兼容组，满批立即执行，不满批按首条到达时间计算等待上限；新增请求不延长旧组的等待窗口。忙碌 Worker 的计算等待仍受队列期限限制，max_wait_ms 不是整个请求的延迟保证。

合批等待计入队列期限，在实际进入算法前再次检查取消、期限及共享执行归属。共享队列仍以数据库时钟计算期限，领取任务代表 Worker 已获得执行归属，可能尚在收集合批输入。运行中的单条取消只影响该条最终响应；共享计算结束前不释放其名额，不打断其他条目。单条结果校验失败只影响对应 Task；整体异常或结果数量错误使本次参与计算的 Task 失败，不隐式重试算法。当前实现要求 serial + thread，明确拒绝普通 Graph、外层引擎二次合批、流式合批和进程批处理组合；算法内部动态合批仍走 engine 模式。

显式调用使用 `POST /v1/server/{name}/deploy/batch`，请求包含 1–64 个 items 与 sync/async mode。每个 item 使用 inputs、parameters 和可选 idempotency_key，继续产生独立 Task；不新增批任务实体。整体身份、请求结构或数量不合法时，在接收条目前返回整体错误。条目进入接收阶段后，按输入顺序返回 index、accepted、status_code、task_id/结果或 error；200 表示批量响应已生成，条目仍可能失败，async 且有已接收条目时返回 202。成功接收的条目不因其他条目失败而撤销。重试逐条携带原幂等键；批量接口不接受整体 Idempotency-Key，避免让一组部分接收的请求拥有含糊的全局重试语义。接收期间入口被 Reload 替换时，尚未接收的条目返回冲突，不混用新旧配置。

`scheduling="concurrent"` 是同步算法对共享对象可跨线程执行的显式声明；factory/init/deinit 在所属线程运行，deploy 在有界的执行线程池运行。同一个 Graph 不能启用此方式。取消和等待超时不能终止同步原生线程，计算及清理实际结束前仍保留任务名额；需要硬终止时采用独立进程的串行 Worker。

三个不同期限：

- 排队期限：开始执行前已过期，记录 expired，绝不再运行 Graph。
- 执行期限：先协作取消；需要硬终止时结束隔离 Worker，并记录受影响任务。
- HTTP 等待期限：连接结束不代表原生计算结束；保留任务和资源，按 disconnect 策略继续或请求取消。

当前同步 HTTP 使用 `execution.http_wait_timeout_seconds`，默认 60 秒、最大 3600 秒；请求的 `wait_timeout_seconds` 只能缩短上限，非法值在准入前拒绝。等待从确认任务已接收后开始，不包含上传、校验和数据库准入提交。超时返回 504 `wait_timeout`，携带 `accepted=true`、`task_id`、`status_url` 和 `Location`；不会取消任务或提前释放容量及文件引用。查询、幂等重试和显式取消沿用已有接口。

同步批量在全部准入尝试结束后共用一个结果等待窗口，200 响应中逐项保留已完成结果或 504 与任务标识。async/stream 请求不接受该参数。Python Deploy/批量调用默认仍无限等待，显式指定期限时复用入口上限。HTTP 等待配置不参与共享队列执行配置摘要，副本可以采用不同等待策略而继续共享同一组任务。

同步 HTTP 连接独立于计算容量计数：Server 参数 `max_sync_connections`（默认采用 max_inflight_tasks）限制每实例总数，已有鉴权配置可选 `max_sync_connections_per_subject` 限制每身份，同 subject 多 key 合并计数。在任务准入前检查，满额返回 429；批量占一个连接，幂等重复等待各占一个。算法公共 Deploy 依赖复用限制，名额覆盖响应转换和发送，异常与断开后释放。每次正常响应发送限时 5 秒。已接收计算保持 Server 归属，客户端断开只结束其等待；自动取消策略尚待补齐。

任务查询、显式取消、管理与异步提交不占同步名额，SSE 保留独立限制。Redis 副本各自限制本地连接，任务共享容量仍由 DB 管理；身份连接上限不是跨副本配额。HTTP 网关对上传前连接和任意自定义路由的限制、任务/文件/速率配额需要独立处理。

直接 Graph 对象的线程模式不能承诺硬终止原生计算。要求硬期限的入口必须使用进程隔离。结束一个共享 Worker 会影响它的其他任务；需要独立故障范围时使用独占 Worker。

请求结束前分离可变输出，恢复动态参数和请求路径，释放临时对象。原生执行失败、同步失败或无法恢复的状态污染后，关闭对应 Graph，下次按配置重建；不把校验失败等普通请求错误当作模型损坏。

**10. 流式输出与事件**

保留现有任务日志/进度机制，统一事件为 start、progress、delta、result、error、done，包含 task_id 和单调事件序号。算法协议可以转换这些事件为其要求的外部格式。

节点运行百分比属于 progress，Token、音频片段等属于 delta；必须由算法或节点实际输出，不能用进度伪装增量结果。SSE 开始发送后不能再改变 HTTP 状态码，因此错误通过 error 和最终状态事件表达。

代码生成器的通用约定：通过 `streaming.enabled` 声明能力，每次 yield 的 JSON 值形成一个 delta，最后一次 yield 作为最终输出并验证输出 schema；不使用生成器 return 值。同步和异步调用也可消费该入口，返回或查询同一最终结果。开始执行时持久化 start，终态事务同时写入 result 或 error 以及 done；result 可通过已有任务状态 URL 引用最终结果。事件数据包含 task_id 与 sequence，SSE id 使用相同序号。进度事件仍由实际进度源提供，不从产出数量推算。

事件保留启用时，`streaming` 配置限制 `max_events`、`max_event_bytes`、`max_duration_seconds`。线程在产出边界协作取消，异步迭代可以协作超时；无法保证阻塞原生代码立即中断，需要硬期限时使用进程隔离。事件读取暂时失败可发送没有序号、`terminal=false` 的可重试 error 并关闭连接，不将传输故障伪装为任务终态。任务事件清理后的序号缺口必须有明确的保留范围响应。

网络发送与计算之间使用有界缓冲。慢客户端触发背压、断连或可重放缓冲策略，禁止无限累积。长连接有心跳、空闲超时、权限检查和连接数限制。

断线续传只有在事件保留启用时提供，使用事件序号或 Last-Event-ID；超出保留范围返回明确错误。Redis 即时广播可用于非关键进度通知，要求重放的结果使用保留的事件日志。任务最终结果独立持久化，不能只存在于连接中。

WebSocket 用于确有双向数据需求的音视频等入口；普通流式文本默认 SSE。实时会话状态隔离和最大持续时间由对应算法声明。

已接入同一 Task 的通用双向 JSON 输入：`streaming.duplex=true` 时异步生成器获得 `input_stream`，原输入/参数保持不变。HTTP `POST /v1/tasks/{task_id}/inputs` 和 WebSocket `/v1/tasks/{task_id}/stream` 共用按序号持久接收，客户端重复同内容可重放确认，乱序或冲突拒绝。0030 迁移在任务中保存输入限额与消费位置，并增加内部输入记录表；不增加公开 Session 或工作流配置文件。默认 64 条待消费输入、一个额外结束标记，输入/输出分别应用现有事件数量/字节限制。文件引用同事务登记，任务清理级联删除输入。Worker 按原任务 attempt/token 读取，取消、终态或失去执行归属后拒绝读取；线程、进程、引擎和 Redis 共享 Worker 使用同一逻辑。

WebSocket 复用输出事件序号，使用 `after` 重连；输入确认不等于算法处理完成，断线继续保留计算。SDK Bearer 鉴权、任务归属、入口权限、Origin 检查、请求限流及共享 SSE 连接总量已接入。连接 60 秒、接收空闲 30 秒、发送 5 秒和心跳 10 秒限制；不接收二进制帧，媒体片段格式由算法在 JSON 中定义。启用审计时输入写操作复用元数据审计，握手、拒绝、断开和只读连接已接入同一审计，浏览器调用鉴权仍需补齐。此通道不代表具体模型协议或真实音视频引擎已验收。

**11. 启停、重载、重启和资源保留**

入口状态为 stopped、starting、ready、reloading、stopping、failed。任务状态与入口状态分开。ready 必须表示路由实际可以接收执行任务。

Reload 的默认流程：读取并校验本次配置 → 在可用资源下初始化新 Graph → 预热 → 切换新请求 → 排空旧请求 → 释放旧 Graph。失败保留原入口及其调用配置。任务接受时固定其配置校验值和执行归属，已排队和执行中的旧任务继续使用原 Graph；新旧实例使用同一个公开名称。旧任务全部终结前保留所需配置和资源。为限制资源占用，同一入口上一轮重载未完成排空时不接受下一轮重载，返回可重试的冲突状态。

预热通过现有 `execution.warmup` 配置输入样例，例如 `[{"inputs":{"text":"warmup"},"parameters":{}}]`，不新增执行对象或单独工作流。默认空列表；最多 16 个样例，每个不超过 1 MiB，文件使用已有 `file_id`。每个 Worker 初始化后按样例逐次运行，输入默认值/字段/类型和输出按正常 Deploy 路径检查。Graph、代码、流式和引擎均支持；动态合批每个样例走一次单条 batch，特定批形状的准备可由已有 `init()` 完成。

预热不登记用户 Task、事件或文件输出。Graph 输出仍实际计算和校验，受管理输出在临时目录内处理后清理；配置引用的输入文件保留到配置和运行引用释放。自定义代码/节点自身产生的外部副作用不作回滚承诺。重新创建 Worker 时重新预热；共享队列已明确停止的配置在恢复时跳过初始化和预热。进程硬终止遗留的临时目录仍需恢复清理。

`execution.startup_timeout_seconds` 覆盖每个 Worker 的设备名额等待、初始化及全部样例。取得名额后沿用剩余期限，不重新计时。隔离进程可确认终止；普通线程在原生计算返回后检查超时，不能因 HTTP/协程计时结束就释放名额或资源。异步初始化取消后仍须等待清理，阻塞原生调用同样不能硬抢占。失败或超时不进入 Ready，候选失败不切换在线入口。

启动配置提交与运行切换采用可恢复的顺序，并保留单份上一次可用配置直到切换确认。内部可使用校验摘要、执行序号和原子替换文件，不暴露为版本管理产品。并发 Start/Reload/Stop 对同一入口串行化；重复停止等待同一次释放，不能重复释放原生资源。

编辑器保存并启动在恢复旧共享入口前取得该入口的控制权，覆盖恢复、初始化/替换与附属配置写入；后台同步不能在恢复后、修复前抢先加载旧 Graph。控制权继续使用已有入口控制记录，不新增用户操作或状态。

当前本地实现将控制操作交给 Server 持有，HTTP 等待者断开不取消它；重复 Start/Stop 等待当前操作，Reload 冲突覆盖旧 Worker 排空阶段。配置通过内部写入标识及 DB 条件更新处理并发覆盖和提交回执丢失。Stop 先确认关闭意图持久化，再释放 Worker。所有 Worker 的关闭均等待结束，释放失败的旧 Worker 继续跟踪，阻止再次 Reload。上述标识不进入工作流格式或编辑器操作。

共享启停在队列表保存内部控制标识：Start 在模型加载前观察标识，完成准备后条件提交，并原子检查已停止队列是否排空；重复 Stop 同样使旧准备失效。条件提交可用相同写入标识重试不确定回执，已有新意图时返回冲突，不能回写旧状态。跟随实例的停止与本机退出不写共享意图；新 Start 已提交时，旧停止流程只结束本机旧 Worker，不持续追赶新任务。慢初始化由入口自己的控制操作持有，不阻塞其他入口的控制轮询。

迁移 0015 保留旧队列容量、在途任务及停止状态，并补初始控制标识。副本需一致升级，新标识不能约束旧代码的无条件更新。首次 Graph 工厂自动识别前若未知队列配置，发现已停止队列后只保留识别结果并返回冲突；重新 Start 才从已知控制状态准备。工厂结构漂移拒绝切换并保留原配置。HTTP 控制幂等见下文，完整跨重启操作结果对账仍需后续实现。

共享 Reload 使用迁移 0016：以命名空间与入口名称确定活动配置，候选配置、旧配置和 Worker 引用保存在现有 DB 中；不增加对外管理对象。配置内容及文件保护复用 `server_configs`。模型加载发生在事务之外，全部候选 Worker 就绪且原启停状态未变化后，事务同时关闭旧队列接收、打开新队列接收并更新活动配置。旧任务继续使用原队列；已登记旧队列的迟到 Start/Stop 被拒绝。未排空任务或未确认物理退出的 Worker 保留配置引用，阻止后续重载。当前已接入 Server 启动、运行时初始化/切换/关闭、副本跟随和原有 HTTP Reload 接口。编辑器停止后更新也在确认原停止意图未变化后准备并启动新配置。副本仍使用过期配置时返回可重试冲突，就绪检查不会把该副本算作可用。

本地工作区保存内部入口关联，共享 DB 保存唯一活动配置及资源引用；已知旧配置的代码注册在启动时跟随当前配置。工厂必须来自显式可信注册，不能从持久化内容动态导入代码。相同配置 Reload 使用新的内部队列，避免重开历史队列。运行中的 Server 可通过再次 Stop 重试已确认退出后的 DB 清理，失败初始化和 Reload 候选的原归属保留至清理确认，不重复模型 deinit；物理释放抛错仍保留原错误与占用。控制者崩溃后的完整请求结果对账、整个 Server 关闭已销毁依赖后的恢复及跨主机/未知旧版本的 Worker 引用恢复仍需实现；本地模型资产跨主机分发也尚未完成。普通运行中提交恢复不能替代这些故障验收。

迁移 0018 为未提交的共享切换记录候选运行引用及控制操作归属。控制者和每个隔离子进程持有同一内部文件的共享 OS 锁；子进程在任何模型初始化之前加锁并检查撤销标记，持锁至实际关闭或进程退出。恢复者取得独占锁，并核对内核启动 UUID、文件设备/节点标识及操作归属后，先 fsync 撤销标记，再在命名空间事务内清理候选 Worker/文件引用和候选配置。事务失败保留 DB 记录，后续重试不撤销磁盘上的拒绝标记；多个恢复者不重复释放。恢复只撤销未提交的更新，不改变当前配置、任务或新的停止意图，也不自动重复有副作用的预热。

原锁文件永久保留，防止延迟启动的子进程绕过撤销；Python 对象丢失引用不自动释放控制锁，必须确认关闭或等待 OS 退出。当前自动恢复只启用于可取得内核启动 UUID 的 Linux/macOS，同一工作区、同次系统启动的原文件；复制的工作区、跨主机、缺失/损坏文件、未知旧版本归属和 Windows 暂不据此回收。POSIX 使用 `flock`；Windows 锁实现参考 [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)，但尚未启用 Windows 启动身份验证与自动恢复。系统重启后接管、撤销记录的有界回收及未知旧版本的物理退出确认仍属于待完成范围。

迁移 0019 把同一退出证据扩展到普通共享入口、恢复中的旧 Worker 和运行任务。模型加载前持久化内部运行归属，即使 Graph 工厂尚未发现 schema、尚未登记 Worker，也能定位初始化崩溃的资源引用。正常关闭仅在没有待对账运行任务时移除该记录。任务领取在命名空间锁内核对 Worker 就绪、运行归属与未撤销状态，并把归属写入任务；旧版任务保持空值，不推测关联。

确认物理退出后，恢复者先在 DB 中禁止该实例继续领取，再有界读取其运行任务。存在本地结果时校验任务、尝试、消费令牌及运行归属后回放；结果缺失则按已记录取消意图标记取消，否则标记 `worker_lost`，不自动重跑。终态仍复用原有任务事务，容量和事件只提交一次；提交回执丢失可继续对账。全部任务完成才事务释放 Worker/文件引用与运行记录。损坏结果保留占用和引用，但不会阻塞其他实例；Server 关闭等待恢复事务结束再关闭 DB。活动队列后台同时有界清理 DB 已终态的 Redis 消息；停止/退役队列的整体键回收仍需补齐。

迁移 0017 区分已建立入口和已确认的首次初始化失败。只有全部本机 Worker 完成启动检查才确认就绪；失败时必须先确认 Worker 物理退出，再记录失败。新配置自动修复仅用于从未就绪、无任务且无运行引用的首次失败入口，继续通过候选初始化和原子切换完成；已建立配置不能因所有副本退出而被自动替换。历史数据保守视作已建立，编辑器的显式 Update 可以直接关联并修复已有工作流。Stop 与修复仍使用条件写入协调，准备前后的新停止意图均使旧操作失效。

重启恢复根据旧队列中实际存在的待执行任务加载旧配置，不把当前 schema 用于历史任务。恢复 Worker 只处理原队列，当前入口保持新配置；多副本仍依靠任务条件领取协调。私有目录中的旧结果记录先按原执行归属回放，已有结果不重新计算。旧待执行任务清空且本机执行结束后释放恢复 Worker。无可回放结果且没有退出证据的失联运行任务继续保留占用；已登记实例确认退出后按迁移 0019 的规则终态对账，不自动重跑。跨主机私有结果可达性及未知旧版本归属仍未解决。

跨重启恢复要求仍未全部实现：运行中临时 DB 故障可以重试同一次配置提交；若 Server 必须退出而提交结果仍未知，则明确返回 `configuration_unconfirmed`（共享控制为 `shared_control_unconfirmed`），重启按 DB 实际内容恢复。此时不能承诺旧配置一定保留，也不能把重启视为原控制请求已成功。

迁移 0020 增加内部 HTTP 控制请求记录，复用 request_id、管理身份、入口和现有控制路由。Start/Stop/Reload/编辑器保存并启动支持 Idempotency-Key；命名空间内记录接收及原始响应，同 key 同正文重放，不重复保存工作流、初始化或更新模型，改动操作或正文则返回 409。共享副本使用 Redis 命名空间确定作用域；独立 Server 使用持久工作区标识。终态至少保留七天，后台每次最多清理 100 条；未确认记录不自动过期。持久接收后默认等待五秒，可配置每次请求等待 0–60 秒，未完成返回 202 和已有 `/api/server?request_id=...` 查询位置。接收确认另外最多等待五秒，未知结果返回可重试 503 control_unconfirmed；不声明 accepted，也不在未知原始记录 ID 时给出状态地址。POST 响应返回原 Idempotency-Key，没有提供时由请求 ID 生成，客户端可用它重试同一操作。完全丢失响应仍要求客户端事先保留 key；key 为 1–128 个可打印 ASCII 字符。状态查询 HTTP 等待最多五秒；POST 已确认接收后遇到结果查询不可用，返回已有记录的 202。后台事务和操作仍由 Server 持有，HTTP 期限或断连不取消它们。同实例合并相同 key 的在途操作及相同记录的在途查询，最多分别 64 个；新工作满额返回可重试 503，不丢弃未确认操作。记录读写使用独立四线程池，与 Deploy 的公共执行通道分离；SQL 的持久唯一性继续负责跨副本幂等，无新迁移或公共实体。

HTTP 控制由 Server 持有，客户端断连只结束等待；关闭时等待操作及记录提交，已结束操作在关闭期间仍尝试提交一次，关闭期间不无限重试，但仍等待在途驱动调用实际返回；已通过 `database_timeout_seconds` 配置连接池、SQLite 锁等待、MySQL socket 读写及 PostgreSQL 驱动等待期限，超时保留提交未知语义并丢弃坏连接；它们不是整个事务或关闭流程的统一总期限，DNS/文件系统/长 CPU 查询等边界和完整关闭期限仍需补齐。终态响应跨进程重启可重放；只有 HTTP 控制进程的同工作区同次系统启动退出证据时，可以将缺少结果的记录置为未确认并返回 503，但不能根据该证据回收模型，也不能自动重跑操作。完整的崩溃时操作结果对账、跨机器退出证明仍未完成。

编辑器负责 key 与查询重试，Start/Update/Stop 的用户操作不变。网络读取十五秒超时、最多两次连续重试、整体查询十五分钟；代理错误或正文断开继续使用原 key。只接受同源且含单个 request_id 的状态地址。未确认 key 当前仅在页面内存保存，刷新后需要先检查入口状态；持久客户端自行保存 key。此逻辑不要求用户管理新的业务实体或编辑额外的配置。

新旧模型无法同时装入内存时，预检查失败并明确说明；用户可以显式选择停机重载。不得自动先关闭旧模型，再声称失败保留原服务。

默认 managed 资源策略：

- 保存正在运行的 workflow.json 和 workflow.server.json 的独立内容，草稿变化不影响当前内容。当前通过 `server_configs` 与文件引用表在同一数据库事务中保存，原工作流 JSON 与编辑器使用的附属配置仍保持原格式。
- 引用已受管理文件，保留其文件 ID 和校验信息；外部本地资源导入 Storage 后由运行配置引用。
- 用户无需逐项创建资源映射。已知模型/文件字段自动识别，自定义节点需声明依赖。
- 删除编辑草稿或外部原文件不删除运行配置及其受管理依赖；引用中的文件禁止普通删除，释放最后一个引用后才允许清理。
- 只承诺已声明的资源完整性，自定义代码私自读取其他路径不能获得同样保证。

配置中的 `file_id` 在启动初始化前建立运行引用；保存的工作流另有持久引用。Stop 和 Server 正常退出释放当前运行引用，保存的配置继续保护重启所需文件。Reload 的候选配置及新运行引用先准备好，再替换保存配置；旧运行引用一直保留到旧 Worker 实际释放后。失败初始化、失败释放和数据库写入失败不能把未知的释放结果当作成功；进程异常退出留下的引用不根据计时器或父进程失联自动回收，后续需要确认全部关联计算进程已经结束。

Server 私有目录的 `.server-id` 自动标识当前运行工作区，随目录与数据库备份保存，容器主机名变化不会产生新的配置作用域。旧 `entries/*.json` 在启动时自动导入一次；数据库中同名已保存配置优先，遗留文件不会覆盖后续更新。代码入口的运行引用使用相同机制；不可序列化的 Python 对象仍需由应用代码在重启时重新创建。普通路径资源继续使用受管理副本；自定义资源字段已沿用现有 I/O 声明接入，缓存自动回收另行实现。

已声明的自定义 Graph 资源复用节点的 io_type_ 与 io_param_/io_params_：Model、Dir 等文件类型可声明任意字段名，覆盖节点本身及 param_/param、路径列表与嵌套节点。中间节点显式设置的 I/O 类型也必须序列化。启动时只改运行副本，输出与请求绑定节点不作静态资源复制，is_path_=false 不解释为模型文件。声明的相对路径只按工作流目录解析，缺失路径或不支持的值在初始化前失败。直接 Graph/factory 在原对象 init 前写入准备好的资源路径，不替换 Graph/Node/Edge；JSON 入口的保留路径随现有配置保存。工厂成功初始化/预热后的资源对应关系复用现有配置表保存；同一注册入口的重建、多 Worker 和 Stop/Start 固定使用已加载内容。新 Server 须显式注册工厂，在同一工作区与入口按节点类型、路径和原声明匹配缺失来源；仍存在的来源可重新准备。相对路径核对注册时的解析目录，避免跨目录借用同名资源；绝对路径保持原有含义。恢复副本先核验摘要，失败加载不覆盖上次保存的对应关系；数据库记录不导入代码，不新增配置文件、表或用户操作。JSON 入口及重复导入现也核验已有副本摘要、缺失内容与路径范围。模型字段可复用原 file_id 引用，保存的工作流保留 ID，Worker 在反序列化和 init 前通过现有 Storage 下载/校验并准备路径。Dir 引用要求 ZIP，沿用受限归档校验并在私有临时目录解包；上传仍受 storage_config.max_bytes 限制，归档及解压后总量上限为原 64 MiB 与该配置的较大值。运行引用在读取和初始化前建立，工厂资源记录中的 ID 复用既有配置引用表保护，失败候选关闭后释放运行引用。此接入适用于常驻 Deploy；原编辑器一次性 Run 的解析及排队期间引用保护、更多原生模型节点、资产回收与跨主机分发仍需后续完成。

可选 reference 策略直接使用用户路径，适合巨大模型或开发场景，但不保证源文件删除后可重建。必须显式配置，页面和状态接口显示该限制。

对象存储文件使用不覆盖的对象 key 或经验证的对象版本引用，并记录内容校验值；ETag 不统一当作内容哈希。下载到 Worker 本地缓存后验证，写临时文件再原子完成，Graph 获取本地路径。缓存正在使用时禁止清理。

重启只恢复已确认可用且 restore_on_restart=true 的入口。未完成的 Reload 不自动替换上次可用配置。代码入口需要可导入工厂和可用依赖；临时闭包或仅存在于内存中的 Graph 不承诺跨进程重启恢复。

崩溃时未确定完成的任务标记失败或等待人工处理。只有算法明确声明可重试且资源输入已保留时才自动重试；模型恢复与任务自动重跑是不同操作。

**12. 数据库与数据模型**

采用统一的关系数据库访问实现，建议使用 SQLAlchemy 管理方言、连接和事务，Alembic 管理迁移；驱动按后端选装。SQLAlchemy 列出 SQLite、MySQL、PostgreSQL 方言，Alembic 提供数据库迁移工具；这不替代本项目自身的兼容测试。[SQLAlchemy 方言](https://docs.sqlalchemy.org/en/20/dialects/)、[Alembic](https://alembic.sqlalchemy.org/en/latest/)

控制请求的已知响应在原请求记录之外保留私有恢复文件：操作返回后先固定响应副本，在控制线程池中持久保存，再提交 DB。归档绑定数据库标识、请求、作用域、管理身份、动作与正文摘要，附带状态码、JSON 响应和校验和，单文件上限 32 MiB。临时文件 fsync、不可覆盖发布及目录 fsync 保证完整副本先于最终 DB 写入；POSIX 0600。不新增公共实体、路由或工作流配置。

原状态查询、启动及有界维护可补写同一请求的已知响应，包括以前的 unconfirmed 状态；DB 终态确认后删除该响应副本与 HTTP 退出标记。模型运行退出证明保持独立。状态提交条件同时包含原 request_id 和未结束状态；幂等过期重用及清理使用条件删除，不能覆盖或删除新的控制请求。恢复只重放历史响应，不调用原动作，也不根据当前入口状态推断操作结果。副本不可用时继续保留未知结果语义；无结果证据、响应尚未生成的副作用、工作区丢失以及损坏/缺失原记录副本的处置仍是待完成的恢复范围。

业务层直接调用 DB 的明确方法，暂不叠加通用 Store/Repository 层。保留 `from .db import DB` 的兼容导出，内部将现有 db.py 迁入 db/。

| 数据 | 用途与关键内容 |
| --- | --- |
| workflows、templates | 现有 ID、名称、位置、封面、说明及时间，保持兼容 |
| tasks | task_id、入口名、可选 workflow_id、身份、状态、时间、期限、输入引用、结果引用、错误、幂等键、执行归属 |
| files | file_id、后端、对象 key、本地位置、类型、大小、校验、权限归属、生命周期状态 |
| server_configs | 每个公开名称的一份已确认配置、来源、受管理资源引用、恢复意图和配置修改校验值；不保存发布历史 |
| task_events（按需） | 需要持久化的审计或事件；高频流式事件可按保留策略放 Redis/文件 |
| server_audit | HTTP、WebSocket、受支持 Python 调用及定时维护的意图、身份、操作、关联 ID、结果观察及保留期限；与业务任务状态分开记录 |
| 访问凭据/审计数据 | 本地 API key 启用时保存密钥摘要、作用域、撤销状态；不重复构建完整用户系统 |

文件引用关系必须可查询，可用关联表实现；不能仅以易失引用计数决定是否删除。任务和当前运行配置都可能持有文件。任务还保存接受时的配置校验值和内部执行序号，用于排队期间重载和迟到结果判断；这些字段不是对外版本对象。

执行状态更新采用事务和条件更新。连接按请求/操作管理，禁止多个线程无保护地共用一个 sqlite3 连接。SQLite 使用适合本地的并发设置；MySQL/PostgreSQL 使用连接池和断线检测。SQL 不依赖某一方言特有的 JSON 查询、自动增长或锁语法来保证通用正确性，差异封装在 DB 内。

接口：get_workflow、save_workflow、create_task、claim_task、finish_task、get_task、create_file、get_file、save_server_config 等，使用领域已有名称。数据库事务不跨越整个模型执行或云文件上传。

有状态任务必须先可靠落库再接受执行。输入正文默认不记入普通日志；需要异步执行和恢复的数据存入受控任务内容或文件引用，并配置保留时间。不可恢复模式明确标记。数据库不可用时，要求记录的入口拒绝新请求，不先执行后假装记录成功。

`execution.task_retention_seconds` 控制已结束任务的保留时间，默认 `null`（不自动删除），启用时最少 60 秒。接收请求时把该设置写入任务；任务终态提交时使用数据库时钟计算 `purge_after`。后续配置修改、其他 Server 的设置或应用主机时钟变化都不能缩短已有任务的期限。没有终态的排队、已派发、运行或取消中的任务不参与清理。

后台按有界批次清理；任务、请求正文、结果、错误、幂等键、事件和任务文件引用在同一事务中删除，失败全部回滚。幂等保证至少持续到 `purge_after`，实际删除前仍可重放；清理后相同幂等键可能创建新任务。任务查询返回可空的 `purge_after`；删除后任务及事件接口返回 404，已打开的事件流报告不可重试的 `task_not_found`，不伪造执行失败或完成事件。Deploy 队列不额外保存内存历史副本；旧编辑器队列保留原有历史行为。

任务清理只释放任务引用，文件内容的生命周期单独管理。文件删除会检查任务、已保存配置、活动入口声明的 `file_id` 和活动下载引用。程序可调用 `await server.cleanup_tasks()`，管理身份可调用 `POST /api/server/cleanup-tasks` 执行一批任务清理，无需新增用户可管理的业务对象。

迁移要求：保留现有工作流 ID 与文件位置；迁移可重复检测；升级前备份；数据库升级只由受控迁移过程执行，多实例不能同时自动改表。跨 SQLite/MySQL/PG 迁移另提供导入导出校验，不宣称修改 URL 就能搬迁现有数据。

当前原生备份已覆盖 SQLite、MySQL 和 PostgreSQL：既有数据库版本变化时在迁移锁内备份，成功发布后才改表；同一当前版本不重复备份，空库首次创建不调用外部工具。SQLite 使用原生备份 API；MySQL 使用 mysqldump 单事务 SQL，PostgreSQL 使用 pg_dump custom 格式。完成文件以不可覆盖的原子发布保留，POSIX 权限 0600。原入口增加 --database-backup / --database-restore 管理命令，不启动模型或 HTTP；恢复仅允许空目标并保留原 ID、正文、事件和迁移版本。MySQL/PostgreSQL 原生工具从 PATH 按需使用，凭据保留在私有临时文件，不进入 argv/错误日志；缺工具、失败或超时均阻止升级。客户端执行期限默认 300 秒，确认子进程退出后删除临时文件；不是对迁移锁或 OS 文件系统的硬总期限。恢复使用同后端格式，PostgreSQL 在单事务执行，MySQL DDL 失败不承诺全量回滚，需新的空目标重试。MySQL 截断且缺完成标记的文件在执行 SQL 前拒绝。此功能不包含外部资源内容或数据库账号备份，维护时须停止相关写入并同步保留资源目录和私有标识。

跨数据库搬迁使用现有 CLI 的 `--database-export` / `--database-import`，或 `DB.export_data` / `DB.import_data`，不引入新的发布对象。JSONL 归档记录当前格式、迁移版本、表列、逐表数量及 SHA-256；源库须当前版本，目标为新空库或当前版本的空表。先在私有副本上完整校验，再按现有外键顺序参数化写入；不执行归档 SQL，不合并或覆盖记录。所有数据在单个事务内写入并逐条读回确认，失败回滚数据；新建的空表结构可能保留。每条记录最多 128 MiB，按记录处理，文件完成后才不可覆盖地发布，POSIX 权限 0600。额外表、视图、物化视图、外部表及自定义触发器明确拒绝，不静默遗漏；MySQL 必须使用 InnoDB 并启用外键检查，非事务表不接受搬迁。

原工作流 ID、路径、任务/输入/事件/文件引用、配置、审计、队列、设备及内部标识保持不变，PostgreSQL 自增序列事务内恢复；MySQL 工作流和模板时间通过 `0031_workflow_timestamps` 保留六位微秒。导出取得同一事务快照，导入锁定空目标，多个进程竞争时只允许一个成功。实际切换仍要求所有相关实例停止写入并一起切换数据库；文件内容、模型、Redis、目录标识及 OS 退出证据不在归档中，需保留原存储，不能从复制的元数据推断旧计算已停止。提交回执丢失时必须核对目标，不默认未导入；操作期限在记录/文件块之间检查，DB 调用沿用既有 I/O 期限，锁及 OS 停顿不承诺硬总期限。

**13. 文件与对象存储**

files.py 负责业务：授权、上传/下载协议、元数据和文件生命周期。storage/ 负责字节内容：put、open、stat、delete、download_to、signed_url。云 SDK 只在对应驱动中按需导入。

| 后端 | 支持要求 |
| --- | --- |
| Local | 安全路径、原子写入、流式读写、清理、校验 |
| S3 / 验证过的兼容存储 | 上传下载、分片、校验、签名访问、异常重试、兼容测试 |
| 腾讯 COS | 厂商驱动，验证凭据、地域、分片、签名地址及错误转换 |
| 阿里 OSS | 厂商驱动，验证同一组公共行为和特有能力 |
| 华为 OBS | 厂商驱动，验证同一组公共行为和特有能力 |

厂商差异不泄漏给算法，但不支持的操作必须明确返回。不能只将 endpoint 改成任意地址就宣称支持所有对象存储。S3 的分片上传、完成及中止需要管理上传生命周期，未完成分片须清理。[S3 分片上传](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)

COS、OSS 使用各自官方 Python SDK 作为实现依据，并锁定测试通过的依赖组合，不把文档示例中的凭据写进代码。[COS Python SDK](https://cloud.tencent.com/document/product/436/12269)、[OSS Python SDK](https://help.aliyun.com/zh/oss/developer-reference/2-0-manual-preview-version/)

文件数量和总字节额度在现有 storage_config 中配置 max_files_per_subject / max_storage_bytes_per_subject，默认关闭；SQLite/MySQL/PostgreSQL 中按精确身份原子检查，同一 DB 的存储位置与 Server 实例共用额度。沿用文件记录的 uploading 状态，在内容写入前预留文件数，逐块写入前预留实际字节；生成输出执行同一路径，进程 Worker 继承配置。上传中、已完成和待删除的文件都计入；内容删除确认后释放，提交结果不明或清理失败时保留占用。启动和现有定期/管理清理对账死亡写入进程；未知退出/异主机情况不能靠超时释放。这里计逻辑文件大小，不重复计算本地缓存及远端副本；所有参与副本应采用相同额度配置。

上传过程采用临时状态：校验配额与声明 → 写入内容 → 验证实际大小/类型/校验值 → 提交可用文件记录。内容写入成功但 DB 失败时清理内容；无法立即清理的孤立文件由后台对账回收。输出文件同理：只有结果记录提交后才成为成功交付的结果。

大文件可由客户端直传对象存储，但必须由 Server 发放受限上传授权并在完成时验证；未验证前不能作为 Graph 输入。签名 URL 按权限和用途生成，短期有效，不作为长期地址写入 DB。

文件访问默认通过 file_id，禁止外部调用者指定任意服务器路径。支持输入目录、临时目录和结果目录隔离。删除检查身份及运行/任务引用；清理任务不能删除排队任务或运行 Graph 所需文件。

Storage 可设置 `retention_seconds`，默认 `null`，启用时至少 60 秒。文件写入元数据时按数据库时钟记录最早可清理时间 `purge_after`；这是从文件生成开始的保留时间，引用始终阻止删除，不在释放最后一个引用时重新计时。修改 Storage 配置只影响随后创建的文件。没有过期时间的正常文件继续保留；失败任务生成的未交付输出在任务终态提交时解除生产任务引用并进入清理范围，输入文件仍受任务记录保护。

Graph 输出文件元数据与生产任务引用在同一事务中创建，验证任务仍在运行且调用身份、attempt、worker_token 匹配；任务完成前不能被清理。结果提交回执丢失时，已提交成功任务的输出仍保持引用，失败清理不能删除它。读取文件的 HTTP 响应在实际内容传输（含 Range）结束或取消后才释放引用；程序内读取可用 `with storage.open(file_id)`。签名 URL 在有效期内阻止自动清理，文件所有者显式删除仍可使 URL 提前失效。

本地文件用存储目录内自动生成的标识区分清理作用域；远程文件按已配置的后端、桶和前缀区分。多个本地目录共用数据库时不会相互删除内容。升级前没有作用域的旧文件不自动回收；显式删除时验证本地内容归属并绑定作用域，后续失败可重试。需要保留或搬迁数据时同步保存这些私有标识和内容。

清理先在 DB 事务中复查引用、签名保留期及到期时间，再标记 `deleting`，随后删除内容和元数据。中断或失败保持删除状态，每次扫描有数量上限，失败项退避 60 秒；其他可清理文件继续处理。`await server.cleanup_files()` 和管理接口 `POST /api/server/cleanup-files` 返回本批扫描、删除、跳过及失败数量，后台也定期处理。当前回收当前本地目录和云对象；其他 Worker 的残留缓存、普通模型资源目录及缺少退出证据的崩溃遗留运行引用仍需后续单独恢复和回收策略。

远程资源下载限制来源和访问范围，不让普通 Deploy 请求变成任意 URL 下载器。针对视频、音频、图片和压缩内容，除传输大小外还限制解码后的资源消耗。

**14. Redis、分布式任务与一致性**

Redis 是可选的缓存和协调设施，不是唯一业务事实来源。单机默认使用每入口独立的本地 TaskQueue；启用共享队列时使用相同的任务接口。共享表示同一入口可被多个 Worker 消费，不表示所有模型混在一个全局 FIFO 中。默认按部署命名空间和入口名划分队列/Stream，只有匹配的 Worker 才能领取；需要物理复用时也必须保持同等的路由、容量和公平性。

任务队列建议基于 Redis Streams 消费组，保留确认和待处理消息恢复机制。Redis 的 XREADGROUP 记录未确认消息，XACK 确认消费；应用仍需处理重复交付和数据库一致性。[XREADGROUP](https://redis.io/docs/latest/commands/xreadgroup/)、[XACK](https://redis.io/docs/latest/commands/xack/)

提交与执行步骤：

1. 在 DB 保存 pending 任务、幂等键、输入引用和有效期限。
2. 将 task_id 投递到 Redis；投递失败保留可补发状态，由后台扫描补发。
3. Worker 收到消息后，在 DB 条件领取任务，获得执行归属和内部执行序号。
4. 领取失败或已终态的重复消息直接按规则确认；过期任务不执行。
5. 执行完成，以相同归属/序号条件提交结果，再确认队列消息。
6. 结果已提交但确认丢失时，重复消息看到终态，不重新执行。

心跳或租约超时不能证明原计算已经停止。迟到 Worker 的结果通过归属检查拒绝覆盖；有外部副作用的算法还需要自身幂等或明确不自动重试。系统不承诺通用 exactly-once 计算。

Redis 还用于限流、短期缓存、Worker 心跳、事件分发。锁必须有所有者和过期策略，但锁不是数据库事务的替代品。模型和大型媒体不直接存入 Redis。

故障策略按用途定义：缓存不可用可以回源；共享队列不可用停止接受无法保证投递的新任务或明确返回已持久化待调度状态；安全限流不可用默认拒绝受保护请求。不得静默切换到每个实例各自的本地队列，造成重复执行。

Redis 和 DB 恢复后进行任务及事件对账。扫描和回收有时间、数量边界。集群命名空间、连接池、认证/TLS、超时和重连均可配置。

同一入口的 Start/Reload/Stop 在多实例中由一个有执行归属的控制者协调，并以 DB 条件更新最终提交，不能只依靠进程内锁。仅将相同配置且已就绪的 Worker 纳入当前调度集合。切换不要求所有机器同时完成，而是只向已经确认的集合派发新任务；旧集合处理固定归属的旧任务。API 实例的本地状态缓存失效时重新核对，不能派发到过期配置。Redis 连接恢复或控制者更换后，迟到的控制消息必须通过内部执行序号被拒绝。

**15. HTTP 协议与身份标识**

保留现有 `/api/workflow`、`/api/queue`、文件与 WebSocket 接口的兼容行为。新调用协议独立定义，不能直接改变老前端的响应结构。

旧编辑器 Run 可以在发送前生成 UUID，并通过 `/api/queue` 的 `Idempotency-Key` 作为 task_id 提交；不带该头的旧调用保持每次创建新任务。同一持久工作区下，相同 key 与正文返回原任务，正文变化返回 409，重试不会重新派发其他副本持有或已经结束的任务。前端对未确认请求保留原序列化正文，Retry 复用原 ID，不受画布后续修改影响；通过 `/api/queue/task/{task_id}` 恢复状态，WebSocket 只补充实时进度。该 Run 请求头要求规范 UUID，与 Start/Reload 的通用控制 key 格式区分；不需要新增配置文件或用户实体。同一浏览器标签页会话内通过 sessionStorage 保存当前任务与原请求，刷新恢复已有标签页及未保存工作流的提交快照，不自动重发。已完成任务的 String/Bool/Num 展示预览与终态一起保存到历史记录，状态查询和实时完成消息均返回相同 outputs；因此观察中的页面刷新、断连与 Server 重启可恢复结果，避免依赖单次 memory 消息。预览仅保留 JSON 安全值，限制节点数、值数和 UTF-8 文本容量，截断明确提示；完整原生对象持久化仍单独处理，已声明文件输出按下述机制保留。原任务确认结束后清理；浏览器存储不可用时明确提示只保留当前页面内恢复能力。跨浏览器会话恢复及服务端保留清理策略仍需完善。

`/v1/server/{name}/schema` 统一描述 Graph 和代码入口，不另建同义接口。模型列表描述可调用能力，不假定一个 Graph 只有一个权重模型。

通用请求示例：

```json
{
  "inputs": {"image": {"file_id": "file_example"}},
  "parameters": {},
  "mode": "sync"
}
```

mode 为 sync、async 或 stream，只有入口声明支持的方式可以使用；可选调用期限受 Server 上限约束。流式模式需要一致的 Accept 和响应类型。专用算法协议可以使用自己的请求结构，但转换后进入同一执行路径。

同步成功返回 200 和 task_id、outputs；异步或尚未完成的控制操作返回 202 和查询位置。排队满/配额不足返回 429，未就绪/必要依赖不可用返回 503，输入错误返回 422，内容冲突返回 409，权限错误为 401/403，文件过大为 413，支持的同步等待超时返回明确的 504 和已接受任务标识。

身份任务额度使用 auth_config.max_inflight_tasks_per_subject，默认关闭；同一 DB 中按身份统计全部入口的非终态 Deploy 任务，接收检查和任务写入在同一事务完成，不依赖 Redis。标准/算法调用与批量条目进入同一准入，幂等重放不重复占位，额度满返回 429。取消意图及断开观察不释放任务名额，持久终态才释放；启用配额和升级保留旧任务占用。无 owner 的 Python 提交属于匿名身份；所有副本须保持额度配置一致。

请求速率沿用鉴权配置中的 `request_rate: {"requests": 60, "window_seconds": 60}`，默认关闭。每个身份最多突发 requests 次，以 requests/window_seconds 每秒持续恢复；同一身份的多个 key、入口、标准与算法专用 HTTP 路由共用额度。认证成功进入公共依赖后计数，幂等重试及查询也计数，批量和流连接各按一个 HTTP 请求计数；健康/管理接口不占额度。超额返回 429 与 Retry-After。无 Redis 时按实例计数；有 Redis 时按 namespace 跨副本原子计数，Redis 故障返回 503，无本地回退。同一身份活跃计数对应不同策略时拒绝，避免滚动配置重置额度。普通 Python 调用、任务数量、文件字节和上传解析带宽不由 HTTP 请求速率代替，分别提供对应限制。Redis 数据丢失或驱逐会重置计数，持久化/淘汰策略属于部署要求。

统一错误结构包含 code、message、可选 field、task_id/request_id 和 retryable。内部堆栈、凭据和任意本地路径不直接暴露。

Start、Reload 和可重试 Deploy 支持 Idempotency-Key，按身份和入口限定作用域，保存请求摘要及原结果。同键不同内容返回 409。启动响应丢失时重试不能再创建一个并行模型。幂等保留期限对外说明，过期后不保证去重。

算法入口声明输入输出、是否流式/可批处理、并发限制和生命周期函数。没有对应能力的入口在注册或调用时明确拒绝，不通过空实现假装支持。

registry.py 保存可信名称和创建入口，按需导入算法依赖。HTTP 普通调用不得提交任意模块名执行。配置缺少 SDK 或算法依赖时给出具体错误，不影响未使用该依赖的其他入口启动。

当前接口为 `server.register("text", "text.server:create_entry")` 和 `server.add(name="text", algorithm="text", options={...})`。注册只保存可信工厂，选择时才导入；工厂返回现有 `Server.add` 的 source/config/model/router 参数，不创建新的执行层。也可直接 `add(..., router=router)`，无需注册。模型初始化仍放在 Graph 工厂或 handler 生命周期中，由 Worker 持有。

算法路由统一挂到 `/v1/server/{name}`，使用 `Depends(get_deploy)` 将专用请求转换为 `DeployRequest`；权限、请求头中的幂等键、Accept、身份、队列和任务记录沿用标准接口。同步结果可映射为专用响应；异步和流式直接返回公共响应对象。所有附加路由均检查该入口的 deploy 权限，辅助资源记录仍需算法检查自身的记录归属。当前支持启动前挂载普通 HTTP APIRouter；首段不能是动态参数、deploy 或 schema；不支持带嵌套路由 lifespan、独立生命周期回调或 WebSocket 的 router。代码注册和路由由应用启动代码重建，不把 Python 工厂写入工作流 JSON 或 DB。

dependencies.py 从当前应用获取 DB、Storage、Redis、当前执行入口和身份。公共类型放 schemas.py；异常放 errors.py；SSE/MIME/请求信息处理按原职责保留，不能因改造 Graph 而遗漏。

自定义算法路由同样经过身份、配额和任务执行接口，不能绕开对应入口的队列或受控引擎准入直接运行阻塞模型。特定协议的逐 Token 调度仍由相应算法实现，Server 提供运输和生命周期保障。

**17. 安全、监控与非功能要求**

API-only 默认不挂载工作流上传、Python 插件上传、模板和调试接口。管理接口与调用接口分别授权。支持本地 API key，并预留与现有身份系统验证结果对接的依赖；权限至少覆盖入口调用、任务查看/取消、文件读写和运行管理。

每个文件、任务和入口操作检查身份范围，不能仅依赖 ID 难猜。CORS 来源明确配置；生产启动时不使用任意来源加凭据的默认组合。TLS 可以由入口代理终止，但代理身份和转发头必须限定可信来源。

旧编辑器维护共享工作流、资源目录及可执行插件，因此整个 `/api` 编辑器范围使用已有管理权限，不向普通调用密钥开放。配置管理令牌或调用鉴权后，编辑器 HTTP 与进度 WebSocket 都先验证管理身份；仅配置调用密钥而没有管理令牌时，编辑器保持关闭。未配置鉴权时保留本地匿名编辑模式，管理 Start/Stop/Reload 仍要求管理令牌。

浏览器通过管理令牌登录一次，获得仅用于 `/api` 的短期 HttpOnly、SameSite=Strict Cookie；模型调用 `/v1` 继续使用调用身份。会话保存在当前 Server 进程中，仅保留摘要，有数量和有效期上限；退出、过期或 Server 关闭后失效，已连接的进度 WebSocket 同样撤销。不同本地运行目录使用不同 Cookie 名称，避免同一主机多个端口覆盖彼此的会话。Cookie 写请求和 WebSocket 必须验证 Origin；命令行 Bearer 调用仍受管理权限检查。前端只在登录时接触管理令牌，成功后清空，不存入 localStorage 或工作流。

浏览器编辑器采用同源部署或同源开发代理。跨来源调用使用显式 `cors_origins` / `--cors-origin` 白名单，不接受通配来源。开发代理默认连接本地 Server，可用 `NNDEPLOY_SERVER_URL` 指定目标；不内置外部主机地址。

请求大小、文件大小、解码资源、队列、并发、连接数、流式持续时间和磁盘容量有上限。秘密值只从环境或凭据设施读取，DB/API key 使用摘要存储，日志脱敏。

Server 自有诊断日志处理器限制单条文本为 32 KiB UTF-8，IPC 仅传递脱敏后的文本及关联字段；编辑器和隔离 Worker 各使用 1024 条日志队列。默认管道/终端、重定向文件、编辑器轮转文件及隔离 Worker 输出均使用有界异步写入；文件目录创建、打开、写入、轮转与关闭仅由独立写线程执行。关闭每个写线程最多等待 250 ms，阻塞的守护线程/描述符可保留至 I/O 恢复或进程结束；不声称 OS 调用已被取消，诊断尾部消息可能丢失。编辑器日志缓存最多 64 个任务、每任务 200 行、合计 4 MiB；WebSocket 最多 128 个待发送操作、每次等待 1 秒。满额或输出失败允许丢弃并计数，不影响任务状态；这些记录不承担审计可靠性。Python/原生输出捕获支持跨行敏感引用和私钥状态，秘密不跨行缓存。自定义处理器、无标识敏感数据和初始化捕获之前的输出仍是独立边界；其他数据库、模型及资源文件系统 I/O 不由诊断队列隔离。

日志关联 task_id、HTTP request_id、入口和 Worker。状态和指标按入口展示排队数、在途数、就绪 Worker、设备放置、限额和拒绝原因；汇总指标不能遮蔽某个入口的拥塞。指标包含排队/初始化/执行/上传下载耗时、任务状态、请求错误、队列长度、在途数量、文件清理失败、DB/Redis/Storage 延迟。指标标签不使用无界 task_id 或原始用户输入。

当前 `/metrics` 使用管理 Bearer 令牌，输出每个 Server 独立的 Prometheus 指标：HTTP 生命周期/首包、准入/Worker/排队时长、已确认终态提交、本地队列、Worker、在途量及 SQL/Redis/文件操作。抓取只读取内存快照；共享队列采用已有心跳采样并附样本年龄，避免依赖故障使监控接口不可用。未知路由/入口固定归类，不使用 task_id、SQL、身份和请求正文作为标签。指标计数随进程重启重置，不作为审计账本；跨进程/GPU 资源及模型首 Token 指标仍需完成；性能基线按最新要求不纳入本轮。详细时间口径见 `python/nndeploy/server/README.md`。

HTTP 请求关联已落地：Server 生成并返回 `X-Request-ID`，首次接收时写入任务记录；幂等重试保留原任务 ID 和原始 request_id，新 HTTP 响应头用于本次访问关联。线程、进程、引擎和共享 Worker 显式携带原始 ID，合批按项传递，旧记录及未启用审计的直接 Python 调用允许空值。结构化事件覆盖 HTTP、任务选择、Worker 调用和已确认终态，字段仅包含关联信息、路由模板、状态与耗时，不记录请求正文、凭据或异常文本。Server 自有诊断日志的上下文脱敏和容量限制已接入，WebSocket 连接现已生成独立 request_id 并写入结构化连接事件；完整部署日志安全及跨进程丢失计数仍需完善。

HTTP 持久审计通过可选 audit_config 启用，复用现有 DB，不改变工作流。对 /api 与 /v1 在操作前写入请求意图和已验证身份，记录路由模板及关联信息，不采集正文、查询串、凭据或异常文本。意图/身份无法确认时拒绝后续操作；响应结果记录失败时保留未确认状态，不把已经执行的业务改成失败。通过现有管理身份查询 /api/server/audit/records，按工作区或共享 Redis namespace 隔离，使用有界分页；已确认结果按保留时间分批清理，未确认意图不按 TTL 删除。独立四线程 DB 池、有界待处理操作和 HTTP 等待期限保护公共执行链路；关闭等待已提交审计 I/O，错误计数不使用身份标签。HTTP complete 与任务成功分别解释，SSE HTTP 200 不能代替任务终态。WebSocket 连接复用同一审计表，记录握手意图、接受前的身份、拒绝与断开；双向输入帧仍单独记录写入操作，不记录正文。正常/异常断开按实际观察结果区分，断开清理不覆盖先前关闭码，审计写入失败保留未确认记录。直接 Python 调用现已复用同一审计：覆盖启动、工作流/入口启停与 Reload、submit/Deploy/批量、双向输入、取消及显式任务/文件/编辑历史清理。操作前持久写入，嵌套公共调用复用记录；HTTP 响应发送结束或 WebSocket 结束后的调用建立新记录，不把 owner 参数当作已验证身份。不新增表、配置或公开概念。定时任务/文件/编辑历史清理、控制响应恢复与清理、审计保留清理及设备退出归属恢复，均在每批动作前写入独立 SYSTEM 意图；无变更批次也记录，不继承启动者上下文。写入失败跳过该项并在后续周期重试；结果记录失败保留未知状态，不重算业务或回滚已完成的删除。整个 Server 关闭、其他内部运行时动作、原始 DB/Storage 调用和未确认记录对账仍需独立覆盖；性能测试按最新要求不纳入本轮。

健康检查区分进程活着和入口可接受请求。一个可选入口失败不必让整个应用不就绪；必需入口和依赖的策略可配置，返回结果不得泄露秘密信息。

非功能验收：无阻塞计算占用 HTTP 事件循环；指定并发下内存/队列有界；重复调用和失败恢复不持续泄漏；平台支持范围明确。按用户 2026-11-15 的最新要求，本轮不做性能测试，优先保证功能正确；延迟分位数、吞吐、性能基线与性能压测不作为本轮完成条件。并发隔离、容量限制、取消及故障恢复仍按功能要求验收，已有运行指标保留。

**20. 故障处理和降级要求**

| 故障 | 必须表现 |
| --- | --- |
| DB 在提交前不可用 | 拒绝需要持久化的新任务，不执行模型 |
| DB 在结果提交时失败 | 不返回成功；处理已生成文件，保留可对账信息 |
| 云存储下载失败 | 未就绪或任务失败，禁止传递半文件给 Graph |
| 输出上传失败 | 任务失败；清理部分上传和本地临时结果 |
| Redis 缓存失败 | 在允许范围回源，记录降级 |
| Redis 队列失败 | 不悄悄改成本地独立执行；已落库任务按策略等待补发 |
| Worker 崩溃 | 入口不可用/恢复中；标记受影响任务，恢复模型；独立 Worker 的其他入口继续工作 |
| 单入口过载 | 该入口背压；不占住其他入口执行通道，应用总量限额仍生效 |
| 共享 GPU 资源不足 | 对相应启动/请求给出明确结果，不通过静默停止其他模型释放资源 |
| 客户端断开 | 执行归属继续有效，按声明策略继续或取消 |
| 新模型显存不足 | 保留旧入口，明确重载失败 |
| Server 在切换中退出 | 重启读取最后确认的配置，处理残留临时文件 |
| 凭据失效 | 返回明确认证/依赖错误，不打印秘密值 |
| 清理失败 | 可重试、可观测，不误删被引用的资源 |

最低验收矩阵：

- 接入：工作流 JSON、直接 Graph、Graph 工厂、同步函数、异步函数、常驻对象、流式生成器。
- 调用：同步、异步、流式、显式批量；动态合批只在声明入口验证。
- 存储：SQLite/MySQL/PG × 公共 DB 用例；Local/S3/COS/OSS/OBS × 公共存储用例。
- 部署：单机无 Redis；Redis 单机多进程；共享 DB/Storage 的多节点 Worker。
- 媒体：文本/JSON、图片、音频、视频、文件、数组/Tensor；包含无效和超限输入。
- 可靠性：连续调用、并发隔离、取消、超时、Worker 崩溃、重载失败、重启恢复、输入/输出清理、重复投递。
- 安全：调用、管理、文件、任务权限；不可信路径和 URL；大小限制；日志脱敏。
- 编辑器：Start 一次操作完成，Ready 后可调用，Reload 失败旧接口可用，保存不修改在线配置，Stop 可观察排空状态。

多模型调度必须增加以下独立验收用例：

| 编号 | 场景 | 必须验证的结果 |
| --- | --- | --- |
| Q01 | A 使用阻塞测试执行器，B 是短任务，各自独立 Worker | 在未命中总量/设备限制时，B 在 A 释放前完成；用同步屏障验证，不依赖偶然耗时 |
| Q02 | A 的待执行队列已满，B 仍有容量 | A 返回 429，B 可接受和执行；不会先把 A 放进无界下游队列 |
| Q03 | 同一 Graph 同时收到两个请求 | 默认不重叠执行，输入默认值和输出不串扰 |
| Q04 | 同一入口配置两个 Worker | 两个独立 Graph 可以重叠执行，模型内存按实际实例计入 |
| Q05 | engine 模式接入可多请求的算法 | 首个流式任务未结束时第二个可以被引擎接受；总在途上限有效 |
| Q06 | 同机两个独立 Server 进程 | 不共享任务队列和控制操作；停止 A 不停止 B |
| Q07 | A 重载失败或所属 Worker 崩溃 | B 的路由、队列和 Worker 保持可用；A 按规定恢复 |
| Q08 | 多入口共享总量或设备限额 | 总量不超限，有保留配额的入口不会被其他入口用尽容量；等待不持有阻塞全局的锁 |
| Q09 | Redis 同组多 Worker、多个入口 | 同名同配置 Worker 共享对应入口任务；不同名称/命名空间不误领任务 |
| Q10 | 资源协调租约过期但计算仍在运行 | 不提前释放名额，不让迟到结果覆盖新归属；核实结束后正确回收 |
| Q11 | CPU、不同 GPU、同 GPU 三种放置 | 前两者没有人为全局串行；共享 GPU 核验实际设备与资源协调正确性，不承诺硬件隔离；性能测试按最新要求不纳入本轮 |
| Q12 | 非受管进程占用 GPU 或新旧模型同时装入失败 | 明确返回资源失败并保留原入口，不自动关闭其他模型 |

Q01–Q10 先用受控执行器验证调度正确性，再以真实 Graph/引擎验证对应能力。Q11–Q12 需要真实设备环境；缺少设备时标记未验证，不用 CPU mock 宣称 GPU 验收通过。

本文件仅确定需求和设计，不承诺这些功能已在当前分支实现。实现过程中的依赖版本、超时和容量默认值应在目标环境中验证并记录；改变协议、运行所有权或数据保留语义时，需要同步更新本文件及验收用例。


画布和 Webui 直接根据现有 Model / Dir 字段提供文件或 ZIP 目录选择，适用于静态资源的中间节点及参数列表。浏览器会话复用 `/api/files/upload`：不传 file_path 时保存到 Storage 并返回 file_id；旧带路径上传不变。选择后沿用 Save、Run、Server Start/Update，无额外发布流程。失败上传保留当前值；异步上传期间锁住该路径列表的编辑，字段名按字面保留。

编辑器 Run 的静态资源字段复用 Deploy 的 file_id 解析和 Storage。接收任务与输入引用事务提交，Worker 在 Graph 反序列化前准备文件或 Dir ZIP；原 JSON、历史请求及本地路径不变。输入引用随排队、执行和终态历史保留，历史清理只解除引用，不主动删除上传的模型。输入不属于 output_files，也不能通过任务输出下载接口读取。迁移 `0033_editor_input_files` 扩展原引用表的方向字段；旧待派发任务恢复时补建引用，输入丢失则明确失败。

编辑器文件输出复用现有 Storage：Worker 在 Graph 完成并 deinit 后、下一个任务开始前保存独立内容副本，迁移 `0029_editor_output_files` 在同一事务内登记文件与原任务的引用。终态查询与 WebSocket 完成消息返回 `output_files`（完整节点路径、file_id、MIME、大小、校验和及下载地址）；`GET /api/queue/task/{task_id}/files/{file_id}` 仅允许读取本工作区已成功任务关联的文件，沿用管理鉴权、Range 与读取保护。成功历史引用阻止文件被提前清理；失败/取消任务解除输出引用并将输出文件交给现有清理流程。保存失败不会交付部分成功结果；数据库提交回执丢失时保留内容，并由写入日志和任务行锁对账。文件保存仍受 Worker 取消监控，但无法强制中断底层文件系统阻塞，实际退出前不释放执行归属。

当前识别已知图片/视频编码节点、ConsolePrint 的保存路径，以及声明文件 I/O 字段的 Image/Video/Audio/File/Binary/Text/Dir 输出节点。每个任务最多 256 个文件，按完整节点路径和字段路径分别保存所有声明字段；支持节点本身、param_ 和 param 的 io_param_ / io_params_，无 I/O 声明时兼容 required_params_。同一字段的重复声明只保存一次；字段支持普通文件、目录及路径列表，工作流 JSON 不改写。Log → History 和 Webui 按字段展示下载及图片/视频/音频预览，画布按完整节点路径和首个声明字段选择对应图片/视频。旧历史没有字段信息时保留原文件和 URL，不从可变路径重新复制；升级使用 0032_editor_file_fields 的可空字段列。任意内存 Tensor/图片对象的自动持久化仍未实现。真实 Chrome 已验证两个嵌套 Graph 中同名输出节点的画布、Webui、历史图片像素及删除源文件后的读取；编辑器复用目录已有的 Graph 元数据补齐 Python Graph 显示注册，不新增节点选择项。其他复杂嵌套编辑交互和预览展开后的整体排布仍需继续检查。

目录输出与文件列表继续使用同一 Task 和文件记录，不增加配置或数据库表。Dir 输出或文件字段指向目录时保存一个 application/zip，下载名称使用 .zip；每个字段可为路径字符串或嵌套路径列表，列表索引以整数附加到 field_path（如 ["reports_", 1]），空字符串及 null 跳过但不重排索引。列表最多 64 层、单列表最多 256 项、一次发现最多检查 1024 个字段及列表值，实际文件总数仍不超过 256；重复声明不重复保存，同一路径在不同索引出现则独立保存。历史及 Webui 按字段/索引提供下载和媒体预览；画布的单文件控件不任意挑选列表中的文件。已提交索引重试不重新读取源路径，尚未提交索引按当前源内容保存；不承诺整个列表跨失败重试的原子内容快照。只能捕获工作流已声明的路径，运行时代码临时生成、未回传到声明中的路径不自动发现。

目录归档保留相对路径、Unicode 和空目录，以 ZIP_STORED 写入匿名临时文件，再走既有大小、身份配额、远程存储及历史清理。生成 ZIP 及未压缩内容均不超过 min(文件上限, 64 MiB)，包括 ZIP 元数据开销；最多 4096 条目、64 层、每个路径最多 1024 UTF-8 字节。根目录按普通路径打开，根内逐级使用目录描述符和 O_NOFOLLOW，拒绝子符号链接、FIFO 和设备；读取前后检查文件与目录变化，发现变化则失败，但不保证对任意外部写入者的原子快照。需要支持描述符相对操作的 POSIX 文件系统，Windows 目录捕获尚未实现。ZIP 上传/读取不解压，校验有界目录信息、相对名称、重复与冲突路径、格式、CRC 和实际内容；仅支持未加密 stored/deflated 的普通文件/空目录，不支持 ZIP64 结束目录、多卷和特殊文件。失败、取消及进程退出会关闭匿名归档；已进入存储的内容沿用原文件恢复和任务清理。



编辑器复用 Log 面板提供 History：按工作区查看完成任务，详情独立显示状态、耗时、持久文本及文件预览，不替换当前工作流或 Run 状态。沿用 `/api/queue/history`，可选 `summary=true` 去掉列表中的工作流正文，`before=<task_id>` 按完成时间与 ID 翻页，避免新任务完成导致偏移分页重复。旧调用返回结构保持兼容。历史保留清理同时处理文件引用与请求幂等，具体策略如下。


编辑器历史保留默认关闭。可用 `--editor-history-retention-seconds 86400` 或 `Server(..., editor_history_retention_seconds=86400)` 启用，最短 60 秒。现有维护循环每轮最多清理 100 条超期终态历史；管理接口 `POST /api/queue/history/cleanup` 可立即执行同一策略，未配置时不删除。时间以数据库时钟为准。清理在一个事务中删除完整历史/请求正文、解除输出文件引用并标记内容待回收；实际文件由原文件清理流程删除，正在进行的下载受读取引用保护。待处理及运行中任务不参与清理。

清理后保留原任务 ID、请求 SHA-256 与最小终态摘要，沿用原任务表 JSON，不增加配置文件、公共实体或数据库迁移。同一正文和 ID 重试仍返回原任务，不重新入队；正文变化返回 409。按 ID 查询仍返回原成功/失败/取消状态及 `outputs_expired=true`、空输出；History 列表不再显示已清理项，失效的翻页游标需返回 Latest。旧终态记录和更早仅有历史的记录在清理时转换，提交回执丢失或晚到的完成重试不会复活已清理结果。跨实例查询和维护会失效本地原生缓存。前端结束等待并在 Webui/当前 Log 持续说明结果过期。摘要当前无限期保留以阻止旧 ID 再次执行，数量有界的摘要/退出归属清理仍待独立设计；不能把本功能称为全部任务元数据都已回收。同工作区任一启用策略的实例都可清理该工作区历史。


## 音频数值端口的实现约定

音频文件沿用原 files、Task 和 Deploy 接口，算法仍是普通 Graph / 代码，不新增服务实体。`array` / `tensor` 复用 dtype、shape、media_type 和容量限制，仅增加描述算法采样率的可选 `sample_rate`。非音频配置不序列化该字段，保持既有配置指纹。float32 帧数据使用 [frames] 或 [frames, fixed_channels]；Worker 负责文件解码、重采样、声道转换及输出编码。支持 WAV / FLAC / MP3 / Ogg-Opus / M4A-AAC，精确限制与调用方式见 Server README；有损编码不保证帧数和值不变。

使用可选 PyAV 在 Worker 内转换，避免新增无法随 Worker 管理的转码子进程。引擎让出事件循环前先复制输出，再在线程转码及存储，取消等待文件操作收尾。代码、直接 Graph 与工作流 JSON 使用同一转换；预热不发布文件。原有插件目录在常驻 Graph 初始化前加载到每个 Worker，编辑器资源目录与 API-only data_dir 各自沿用本地安装路径，不向工作流或调用协议增加插件路径字段。

可选依赖范围为 PyAV >=16.1,<20；16.1 的 Python 下限为 3.10，见 [PyAV 16.1 元数据](https://pypi.org/project/av/16.1.0/)。本地数值/编码测试分别验证 16.1.0 与 19.0.2，不等同于所有 Python、操作系统和中间版本均已验收。
