# SAM3 开发与共享仓库维护边界

日期：2026-11-19。适用范围：chenze 的 SAM3 推理、Graph 和服务适配工作。

## 1. 用户指定的修改边界

用户明确要求：文档放在 `docs/zh_cn/vibe_coding/chenze/`；代码尽量全部放在 `python/nndeploy/segment/sam3/`；在现有 `test/` 下建立 SAM3 专用测试脚本目录；复用公共服务、算子等能力，目录外确有必要的修改或新增文件须先经用户审核。

| 目录/范围 | 处理方式 |
| --- | --- |
| `docs/zh_cn/vibe_coding/chenze/` | 本项目设计、API 交接、验证说明与开发记录集中在此维护 |
| `python/nndeploy/segment/sam3/` | SAM3 Graph、Node、Runtime、数据类型、算法适配及专用 server 入口优先全部放在包内 |
| `test/sam3/` | 可直接新增和维护本项目的测试、验证与诊断脚本 |
| 仓库外本项目运行目录（如 `nndeploy-runtime`） | 虚拟环境、依赖、运行配置、缓存和验证产物属于非公共部分，可直接维护，无需逐次审核 |
| 仓库内其他公共目录/文件 | 可阅读、导入和使用已有能力；修改、新增、删除或移动文件须先提交具体方案并由用户审核 |

2026-11-19 用户进一步明确：不涉及公共部分的改动可以直接执行，不需要逐次审核。上述 SAM3 专用目录和仓库外本项目运行环境均属于这一范围。公共部分的必要改动仍需先审核；不能将仓库外运行环境误判为公共组件源码。

后续若必须越界，先在本目录写清：准确文件清单、问题与触发条件、为什么包内适配不足、拟议改动或补丁、对其他模块的影响和验证办法。用户审核通过后，只实施获批范围。等待期间可以继续不依赖该改动的目录内工作。

该审核要求来自用户本轮指示，不是对仓库通用规范的推断。本文件是在项目目录内记录约束，不修改仓库根 `AGENTS.md`。

## 2. 包内组织建议

保留已有原生推理源码与资产布局，按实现需要增量新增；不要为了目录整齐大规模搬动模型文件。

```text
python/nndeploy/segment/sam3/
  model/、sam/、perflib/、assets/     # 已有原生推理与资产
  model_builder.py                  # 已有 builder
  graphs/                           # 三个高层推理 Graph（拟新增）
  nodes/                            # 输入、业务推理、结果处理 Node（拟新增）
  runtime/                          # 模型、图片上下文、视频会话（拟新增）
  types.py                          # 提示、结果与引用等数据契约（拟新增）
  server/                           # 复用公共 Server 的 SAM3 专用适配
  __init__.py                       # 包内导出，保持按需加载
  requirements.txt                  # SAM3 专用依赖

test/sam3/                          # 自编测试、冒烟与诊断脚本
docs/zh_cn/vibe_coding/chenze/       # 详细设计、使用与验证文档
```

拟新增项不是空目录/空实现清单，按功能实际需要创建。已有 LICENSE、模型资产说明和打包元数据保留其必要位置；详细开发与交接材料集中到文档目录。

本项目继续只迁移和适配 SAM3 推理，不扩大到训练、评测工具、Agent 或 SAM3.1。用户已授权自编专用测试，这与不搬入上游训练/评测/测试整套代码不冲突。

## 3. 公共能力的复用方式

- 直接使用 `nndeploy.dag` 的 Node/Graph/Edge、生命周期、创建器与注册机制。
- 图像/视频输入输出、预处理、算子、结果编码、设备和日志等已有能力满足契约时优先复用；格式差异由 SAM3 包内薄适配处理。
- 服务继续复用 `nndeploy.server` 的执行、任务、Worker、资源、存储、回调等设施；专用协议适配放在 SAM3 的 `server/`。
- 优先采用显式导入或现有插件加载入口注册 SAM3。不要为了自动发现，未经审核修改 `python/nndeploy/__init__.py`、`python/nndeploy/segment/__init__.py` 或公共注册器。
- 包内适配不能通过全局 monkey patch 改写公共组件行为，以绕过目录外审核。
- 不为 SAM3 另造公共 Server、队列、调度器或通用算子框架。现有扩展点不足时，先提出具体缺口和最小越界方案。

服务设计材料中存在拟议接口。接入时核对更新后的实际代码与运行行为，不能把设计说明当作已可用 API，也不能因当前服务未更新自行重构公共 Server。

## 4. 需要审核的典型文件

以下仅是可能遇到的边界示例，并不表示计划修改：

- `python/setup.py`、根依赖或全局打包配置。
- `python/nndeploy/server/`、`python/nndeploy/dag/`、其他算法包。
- `framework/`、`plugin/`、公共 C++/CUDA 算子和 `cmake/`。
- 根 `.gitignore`、公共 CI、`test/config.cmake` 或其他测试公共入口。
- 文档总索引、`docs/zh_cn/vibe_coding/README.md` 或其他人的文档目录。
- `demo/`、`template/`、前端等不在本项目三类目录内的文件。

根 `.gitignore` 当前忽略 `*.json` 等产物。确需版本化的小型工作流/测试资源，优先在授权子目录中设置精确例外；不能直接修改根忽略规则。权重、运行缓存和大型结果不作为源码加入。

## 5. 已核对的仓库规范

核对基线：`chenze` 分支，提交 `b7286d190c61362553ddca1d3628a3913e1f124d`，日期 2026-11-19。后续上游更新可能改变实现细节。

| 依据 | 本项目遵循的内容 |
| --- | --- |
| 根 `AGENTS.md` | DAG/插件组织；Python Node 使用模板；仓库测试根目录为 `test/` |
| 根 `CONTRIBUTING.md` | 分支开发、针对性验证、文档及清晰提交说明；不顺带整理其他模块 |
| `docs/zh_cn/quick_start/plugin_python.md` | 层次化节点 key、显式输入输出类型、生命周期、Creator 注册、参数序列化和 Graph 组合 |
| `template/python/template.py` | `set_key` 与注册名一致；通过 Edge 读写数据；保留 Creator/节点引用方式 |
| `template/python/app.py` | 显式导入自定义节点并复用现有 app；支持插件加载方式 |
| `docs/zh_cn/vibe_coding/always/server_design.md` 的约束与扩展章节 | 公共设施保留在 `nndeploy.server`，算法专用代码位于算法 `server/`；服务管理任务，DAG 管理计算 |
| `test/config.cmake` 与 Python 测试示例 | C++ 测试由现有配置管理；Python 示例同时存在 unittest 和 pytest，本项目可在专用目录独立运行 |

新 Node/Graph 使用 SAM3 命名空间，例如 `nndeploy.segment.sam3.SAM3ImageConceptGraph`。稳定配置可序列化；模型对象、GPU 缓存、视频 session、存储凭证不能写入工作流 JSON。

初始化、执行、释放职责分开。共享 Runtime 必须有明确 owner；不能由一个 Node 的退出意外销毁其他 Graph 仍在使用的资源。依赖保持按需导入，不因导入其他分割算法而强制加载 SAM3 权重。

仓库贡献指南提及向 `main` 提交 PR；本项目当前在从 develop 建立的 `chenze` 分支开发。实际提交上游 PR 时再确认目标分支，本轮不切换、不推送、不创建 PR。

## 6. 测试与验证边界

- 自编测试统一在 `test/sam3/`，使用生产包的真实入口；不将生产实现复制一份到测试中。
- 优先验证提示语义、数据转换、结果/状态生命周期、Graph 注册与序列化、概念到实例交互，以及必要的 GPU 推理回归。
- GPU/模型测试显式接收设备、权重和样例路径；不把个人绝对路径或下载凭证写死在脚本中。
- 轻量测试和需要模型的冒烟测试区分；选择与本次改动相关的验证，不要求每轮重复全套编译/性能测试。
- 测试数据、日志、结果通过临时目录或显式输出目录管理，不污染其他组件，也不因单个测试修改公共配置。
- 接入公共 CI/CTest 等超出专用目录时，仍需用户审核。具体已执行的验证见本目录的环境与回归记录。

## 8. 环境对齐原则（2026-11-19 用户确认）

用户决定：“先按仓库里的规范来，不行再后续我再想办法解决”。

- 优先采用仓库已有的 Python 环境配置、依赖安装和插件加载方式，复用现有部署能力。
- SAM3 专用依赖仍在包内维护，公共依赖声明不因 SAM3 的接入擅自改动。
- 不预先引入按模型划分多环境、多进程桥接或额外容器等定制隔离方案；仓库文档本身提供的普通虚拟环境用法可以正常采用。
- 遇到实际版本不兼容或运行失败时，记录命令、环境版本、错误及受影响功能。按用户随后授权，可在本项目非公共运行环境中使用正常依赖解析和进程级配置解决；无法在该范围内解决时，报告用户决定下一步，不自行扩展为公共组件改造。
- 安装或启动过程如需写入本项目授权目录之外的仓库文件，仍按前述规则先提交具体方案供用户审核。按仓库流程执行不取消维护边界。

以上为环境处理原则；2026-11-19 的实际安装与联合运行结果另见 [运行环境对齐](sam3_environment.md)。
