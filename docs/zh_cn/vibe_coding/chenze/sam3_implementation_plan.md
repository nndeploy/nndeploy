# SAM3 Graph 实现规划

日期：2026-11-19。状态：用户已指示实施；2026-11-19 三 Graph、Runtime、取消、JSON 工作流与通用 Server 验证已落地，详见 [实现验收](sam3_graph_validation.md)。本文件保留实施顺序与后续服务要求。

## 1. 本阶段目标与范围

先交付可在 nndeploy 工作流运行的三个高层推理 Graph，覆盖 SAM3 图片概念、图片实例交互及视频概念/实例跟踪。对内保留可调用、可测量、可替换的计算与状态边界。服务交付继续保留完整 SAM3 能力及 SAM2 协议兼容两条要求，但不在本阶段写死尚待对齐的 HTTP 流程。

| Graph | 主要能力 | 与其他 Graph 的关系 |
| --- | --- | --- |
| `SAM3ImageConceptGraph` | 文本、正负概念框、组合提示、连续查询、多实例与空结果 | 与图片交互 Graph 共用 ImageRuntime/ImageContext |
| `SAM3ImageInteractiveGraph` | 正点/负点、实例框、点框组合、独立提示组、多候选、logits 精修 | 能接续同图概念结果；不把概念概率图当实例 logits |
| `SAM3VideoGraph` | 会话、概念发现、对象点击/mask、传播、结果读取、对象管理、重置/关闭/真实取消 | 概念和实例操作使用同一 VideoRuntime/session；离线任务以后复用它 |

三个 Graph 均按“输入准备 → 业务推理 → 结果整理”组织。输入输出组件满足语义时复用现有实现；不能满足时在 SAM3 包内薄适配。内部计算模块不全部注册为可拖拽 Node，不为每种提示分别创建 Graph。

本阶段不开展 TensorRT/ONNX 导出、torch.compile、算子融合、多 GPU 调度或跨 Worker 会话迁移。图片和视频模型分别按需加载；不承诺三个 Graph 同时常驻同一张卡，常驻策略根据实际显存验证确定。

## 3. 必须先确定的契约

以下是本计划建议，不是已实现 API。进入对应实现步骤前，先把规则写入类型与测试用例，避免把模糊语义固化进代码。

| 契约 | 建议规则 | 验证要点 |
| --- | --- | --- |
| 图像与坐标 | Graph 输入明确 RGB/颜色格式、原尺寸；对调用者统一原图像素坐标，包内转换成原生各分支格式 | 非方图、边界点、正负标签；原生图片概念 cxcywh、实例 xyxy、视频概念 xywh 不混用 |
| 框与范围 | 建议 bbox 用 xyxy、右下端点排他；视频处理范围用绝对帧半开区间 `[start,end)` | 单像素/空 mask、首末帧、反向传播；模型框与最终 mask 外接框分别标识 |
| 概念提示更新 | 明确替换查询、追加概念框、清空提示；视频更换概念显式重新开始并更新状态版本 | 不把视频原生 reset 行为伪装成无副作用追加 |
| 实例提示 | 图片请求包含独立提示组；每组保留候选及质量分数；点更新明确替换/累计 | 不支持的组合显式拒绝；视频当前签名过滤的参数不能静默透传 |
| 概念后精修 | 通过概念结果版本和选中实例，提取有效实例框/用户点进入交互分支 | 同图复用特征；选择不得跨图/跨失效版本；概率不当 logits |
| 引用与结果 | context/session 标识加状态版本；提示变化令依赖旧提示的当前结果失效；保留的历史快照明确标注版本 | 未计算、有效空结果、旧版本三者可区分；读取不隐式传播 |
| 所有权 | 应用/Worker owner 持有 Runtime；Graph/Node 使用注入引用；借用者 deinit 不销毁共享模型 | 一个 Graph 关闭不破坏另一个；显式 owner 关闭释放资源 |
| 并发 | 首版同一个 Runtime 的推理串行；同会话状态操作只由 owner 提交 | 交错访问两张图片/两个会话无污染；取消控制不等待推理锁 |
| 一次性调用 | 自动清理临时上下文；返回可独立使用的结果，不返回已经失效的精修引用 | 多轮精修使用显式持久上下文；结果不引用后续会被改写的缓冲区 |
| 取消后状态 | 建议保留已提交结果，终态为 cancelled；首版要求 reset/close 后才能继续修改或传播 | 不承诺中断任意 CUDA kernel；停止后不得继续提交后续帧；可用性待真实测试 |

需在契约检查点明确、不能擅自声称已知的事项：

1. 双向传播重复帧的最终结果取法、同对象同帧重复 seed 的替换规则；先按原生实际调用行为做对照，再给出明确业务规则。
2. 旧 SAM2 单候选选择、重叠 scenes 和多 seed 覆盖顺序，原文无法还原的部分须标为兼容决策，不能宣称完全复刻旧实现。
3. 仅负概念提示、视频初始概念框数量等原生约束，先验证再列入“支持”矩阵；不公开无效果参数。
4. 上表中坐标端点、取消后 reset 的规则为建议默认值；若已有调用方有不同约定，在写实现前调整契约。

未确定的旧协议细节不阻塞原生 Graph 的共同能力，但会阻塞相应兼容适配交付。

## 4. 内部模块怎样保留边界

首版只提供 NativeTorch 实现。通过原生自然入口及包内显式适配/注入点接入，避免新增一整套空后端框架。包装必须进入真实推理调用链，不能只定义一个未使用的接口。

| 边界 | 需要固定的内容 | 本轮实现尺度 |
| --- | --- | --- |
| Decode / Preprocess | 媒体/帧标识、RGB、resize/坐标变换、dtype/device | 可独立调用的准备函数，优先复用既有解码能力 |
| VisionEncoder | 完整概念及实例/tracker 多尺度特征、位置编码、变换及后端标识 | 适配 `forward_image`；验证特征分支完整，复用时可计数 |
| Tokenizer / TextEncoder | token、语言特征、mask、文本版本 | 分别保留 CPU 分词和编码调用观测 |
| ConceptPrompt / Grounder / MaskHead | 几何提示、查询特征、框/分数、概率/mask 的含义 | 对齐 `_encode_prompt`、encoder/decoder、segmentation heads 的自然边界 |
| InstanceSegmentor | 提示组、候选、质量分数、精修 logits | 复用 `predict_inst` 和原生 SAM heads，不改变候选选择语义 |
| MemoryAttention / MemoryEncoder | 读写特征、对象/帧、状态提交时点 | 保留原顺序及 memory 结构；不能提前写入尚未确定的 mask |
| Association / Controller | 检测与跟踪关联、ID、动作历史、full/partial/fetch 路径 | 首版保留原控制器，只加入必要的观测/取消检查点 |
| Postprocess / Encode / Result sink | 原尺寸恢复、bbox、RLE、多对象、结果版本 | 计算结果与编码/文件导出分开；CPU 结果及时消费/落盘 |

每项契约记录 shape、dtype、device、可变性、生命周期、模型/预处理/精度标识。替换接口的验证至少包含同一真实输入的等价输出和主调用链确实使用该实现。

适配若必须修改已迁移的包内原生方法，仅允许最小的可选注入/观测/取消入口，默认行为不变；记录其与上游的差异，并重新做对应推理对照。不全局 monkey patch，不重命名权重键、不搬动原生目录。

观测随各功能一起交付：Graph 总时长、输入/推理/输出时长、模块调用次数与 shape、图像特征命中、视频实际计算/缓存读取帧数。沿用已有 profiler 标记，按需增加可关闭的测量；GPU 时间仅在启用 profiling 时测量，不在默认路径逐模块同步，也不把父子耗时相加。详细性能优化放在 Graph 验收之后。

## 5. 分步实施与退出标准

### P0：契约与关键机制验证

产出：最小请求/结果/引用契约、功能支持矩阵，以及专用测试目录中的小型验证脚本。

先验证三件事：

- 自定义 Python Edge 类型、Creator 注册、Graph 序列化/重新加载、运行时资源重新注入，能通过现有扩展点完成。
- 同一 ImageRuntime 支持两图交替操作、同图概念后精修；encoder 调用计数证明没有额外图像编码。`predict_inst` 会临时写预测器 `_features`，因此必须验证串行与异常清理。
- 视频 full/partial/fetch 的安全检查点及取消传递。full 路径有 hotstart 延迟，在返回第一帧之前可能已经计算多帧，不能只在外层 generator yield 后检查取消。

退出标准：上述机制可在授权目录内实现，数据/状态规则明确。若现有公共扩展点确实不足，先提供必要公共文件的最小补丁供审核，其他独立步骤继续。

### P1：图片概念的完整链路

产出：ImageRuntime、ImageContext、必要内部适配，以及 `SAM3ImageConceptGraph` 的输入/推理/结果节点。

- init 加载模型，run 复用资源；支持一次性图片和显式图片上下文。
- 文本、正负示例框、组合提示、提示清理、筛选阈值；保留全部匹配实例及概念分数。
- 完成原尺寸结果、RLE、空结果、上下文释放与错误返回；同步加入观测。

退出标准：Graph 调用与当前同环境原生调用对照；非方图、多个实例、无匹配、重复查询通过；重复 run 不重复加载权重，清提示不重算视觉特征。

### P2：图片交互及两条 Graph 联动

产出：`SAM3ImageInteractiveGraph`，共用 P1 Runtime/Context。

- 正负点、实例框、点框组合、独立提示组、单/多候选与连续 logits 精修。
- 概念选中实例 → 交互精修，显式保留提示组/候选身份与结果版本。
- 异常后清除预测器临时状态；先逐组正确处理，不宣称已支持原生 batch 加速。

退出标准：与原生等价；两条 Graph 切换复用同图编码；两图片交错调用不串状态；关闭借用 Graph 不销毁共享 Runtime；释放上下文后旧引用明确失效。

### P3：视频会话、提示与传播

产出：VideoRuntime、VideoSession、`SAM3VideoGraph`。

- 有限、具类型约束的操作集合：建立/查询、概念提示、实例点/mask、传播、读取、移除、重置、关闭。
- 概念多目标发现 → 选对象 → 点击/mask 修正 → 继续传播；多对象、多关键帧必须覆盖。
- 前向/后向/双向及范围适配，保留绝对帧号和对象 ID；记录 full/partial/fetch 的实际路径。
- Graph.run 内消费原生 generator；向有界结果接收器增量提交，返回操作摘要/结果引用。首版不要求 nndeploy Graph 自身支持流式返回，不将活 generator 交给下游。
- 控制对外结果缓存大小；原生 tracker/帧缓存单独记录，不因增加结果接收器就宣称整个模型显存已恒定。

退出标准：以上功能和两会话交错操作通过；更换概念、移除、reset/close 的引用规则明确；缺失帧/空目标/旧结果可区分；结果读取不触发新推理。

### P4：真实取消与视频结果收尾

产出：取消控制、完成帧记录、异常收尾及可读取的结果产物。

- 控制路径只置取消标记，owner 在安全计算边界检查，停止后续帧调度；不从控制线程直接释放正在使用的 GPU 状态。
- 检查点覆盖 full（含首次输出前）、partial、fetch 及双向切换；已发出的当前 CUDA 工作允许完成。
- 取消与“受理取消”区分；保存已提交帧范围，暂存结果不冒充完成结果。
- 正常、失败、取消均清理生成器和临时资源，按约定将会话标记为需要 reset 或已关闭。

退出标准：取消发生在尚有未处理帧时，后续计算/提交确实停止；测量从请求取消到停止的延迟但不预先承诺时限；同一进程可重新建立会话继续运行。没有这一项不能把视频能力标记为完整交付。

### P5：工作流接入与第一版 Graph 验收

产出：SAM3 包内显式注册/启动入口、可生成的工作流示例、使用说明。

- 按模板设置 key、输入输出类型、Creator、参数序列化；使用显式 import/现有 plugin 机制，不修改公共包初始化。
- 可保存/重新加载三个 Graph；模型、GPU 状态、session 和凭证不进入 JSON，加载后由明确 owner 重新绑定 Runtime。
- 提供三个单 Graph 示例，以及“概念选择后精修”“视频概念后修正”的组合示例；组合示例不增加第四类推理 Graph。
- 同进程显式 owner 首先通过；再核对现有 Server/编辑器承载是否维持 owner。不能只凭 `shared_runtime` 命名认为它已实现 SAM3 模型或上下文共享。
- 通过实际编辑器/工作流加载与运行确认可用。若 UI/现有输出节点不能消费 SAM3 结果，先提供包内转换或导出；需要公共改动时单列审核。

退出标准：从实际工作流入口完成图片与视频用例；Graph 生命周期、结果导出、重载和异常路径通过；已有 Server 简单 Graph 测试继续通过。仅 Python 直接调用成功，不算完成工作流部署。

### P6：后续服务、离线任务和 SAM2 兼容

在工作流阶段完成、server 代码更新并核对扩展点后开展，不从本轮规划中删除这部分业务范围。

- 视频离线任务复用同一个 VideoGraph，编排资源、场景、进度、产物和关闭自己创建的会话；优先复用现有任务/存储/回调设施。
- 完整 SAM3 服务提供图片、视频持续交互、离线任务三组入口，覆盖现有功能追踪表 I01–I04、V01–V07、J01–J03、E01。
- SAM2 兼容层保留 `/healthz`、`/imageMask`、`/videoMask` 的字段、同步/异步、busy、回调和导出格式；旧文档无法确定的选择规则另行冻结。
- 最终 HTTP 字段、调用示例及流程待真实部署后补写 API 交接文档，不预先承诺服务框架尚未验证的流式/多 Worker 共享能力。

退出标准：完整 SAM3 服务与 SAM2 兼容分别验收；不以新功能成功代替旧协议兼容，不以原生模型对照代替 API 验收。

## 7. 实施节奏与最终验收口径

顺序为 P0 → P1 → P2 → P3 → P4 → P5；P6 等待服务接入条件明确后继续。先完成一条可运行链路再扩展，避免先造出所有空 Graph/Runtime。每步结束记录改动文件、已支持/未支持能力、验证输入、实际结果和下一步。

观测和必要回归随每一步完成，不等全部代码写完再补。契约/状态测试可不加载权重；涉及推理结果、缓存复用和真实取消时必须使用真实模型验证。GPU 测试使用显式设备参数、已有权重与小样例，先检查可用资源。

第一版 Graph 完成至少需要以下五条链路：

1. 图片概念多实例 → 选中一个实例 → 同图交互精修。
2. 图片独立点/框提示组 → 多候选 → 指定候选连续精修。
3. 视频文本/概念框 → 多目标 → 指定对象点击/mask → 再传播。
4. 视频多关键帧、正反向、结果读取、移除/reset/close，状态版本正确。
5. 真实传播取消 → 已完成结果可读取 → reset/重建后正常运行。
