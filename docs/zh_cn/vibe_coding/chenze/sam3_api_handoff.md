## 0. 服务范围与通用约定

### 0.1 交付范围

提供两组接口，共用 SAM3 推理能力：

1. **SAM3 完整能力接口**：图片概念分割、图片实例交互、视频概念分割与多目标跟踪、持续交互修正、会话与任务管理、结果获取与导出。
2. **SAM2 协议兼容接口**：保留 `/imageMask`、`/videoMask`、`/healthz` 的外部协议，使现有调用方尽量可以直接切换。

SAM2 文档只约束第二组接口。单目标、固定 `object_id=0`、只能从 mask 初始化视频等旧限制，不约束完整 SAM3 接口。

本轮的“功能迁移”指把已经迁入的原生推理能力接入工作流和业务接口，不是再次搬运源码。训练、评测工具、Agent、SAM3.1 不在本项目范围内。

### 0.2 推荐的业务接口分组

对外先收敛为 **3 组 SAM3 业务接口**。这是功能分组建议，最终 HTTP 路由数量等 server 更新后确定。

| 业务入口 | 包含的功能 | 对调用方的使用方式 |
| --- | --- | --- |
| 图片分割 | 概念分割、实例交互、多候选、连续精修及同图上下文复用 | 通过明确的模式区分概念查询与实例修正；一次性请求可直接传图片，多轮操作复用上下文 |
| 视频交互 | 会话、概念发现、点击/mask 修正、传播、目标管理和结果读取 | 同一会话下调用明确的业务操作，保留对象 ID 和跟踪状态 |
| 视频离线任务 | 一次提交视频与概念/实例提示，后台处理并获取结果 | 服务管理会话，调用方主要关注提交、进度和结果 |

另外保留旧 `/imageMask`、`/videoMask` 兼容入口，以及 `/healthz`。任务查询、取消、文件资源和通知优先对接更新后的 nndeploy server 能力；是否需要补充适配，以部署后的实际接口为准。

归并原则：

- 文本、框、点、mask 是提示类型，不各建一套 API。概念模式与实例模式仍有各自明确的输入、输出和校验规则，避免一个含义模糊的框字段承担两种业务。
- 图片上下文、清除提示、视频会话、目标移除属于对应业务入口下的操作，不要求每个功能建立独立服务或模型节点。
- 阈值、单/多候选、传播方向和输出格式作为参数；RLE/bbox/文件导出作为结果能力，不默认单独设接口。
- 概念分割后精修，通过已有入口组合完成，不再增设一套专用接口。
- 不为减少 URL 强行把所有执行方式塞进同一个阻塞调用。传播期间查询与取消仍应可用；需要分离的提交、结果通道在部署时确定。

下文按功能细分章节，方便明确语义和验收，**不表示每章都要新增一个 HTTP 接口**。原功能编号移到附录 A，用于需求追踪。

这次归并不改变内部业务节点设计：图片概念节点、图片交互节点和状态化视频节点仍分别保留。HTTP 入口、工作流节点与内部计算模块不要求一一对应。

第一版建议部署 **3 个推理 Graph**：`SAM3ImageConceptGraph`、`SAM3ImageInteractiveGraph`、`SAM3VideoGraph`。图片入口按模式调用前两个；视频交互与离线任务复用第三个，外层分别管理会话和任务。旧协议通过适配复用同一推理能力，不另建两套模型 Graph。详见 [首版 Graph 划分](sam3_graph_design.md)。

### 0.3 通用数据语义

这里确定数据含义；除旧兼容入口外，具体 JSON 键名、必填项和默认值后续冻结。

| 数据 | 约定/设计目标 |
| --- | --- |
| 图片来源 | 至少覆盖图片内容输入与已创建的图片上下文引用；base64 可复用旧接入习惯。与 nndeploy 文件资源的映射部署后确定 |
| 视频来源 | 至少覆盖已有对象存储视频和工作流可读取的视频资源。对象 key、文件资源标识与 HTTP URL 必须明确区分 |
| 坐标 | 对外统一使用原图/原帧像素坐标；点为 `[x,y]`，框为 `[x1,y1,x2,y2]`。bbox 右下角端点规则在字段契约阶段明确 |
| 原始尺寸 | `[H,W]`，输出 mask 恢复到原图/原帧尺寸 |
| 帧号 | 从 0 开始的全视频绝对帧号；不能把裁剪片段内部帧号直接返回 |
| 场景区间 | 使用 `[start,end)`；场景独立推理时，不默认赋予跨场景对象相同身份 |
| 对象标识 | 视频对象 ID 在所属会话及状态版本内解释。图片概念结果 ID/序号不等同于视频跟踪 ID |
| 候选标识 | 实例交互的候选属于某一提示组；多个候选不是多个独立目标 |
| mask | 对外二值 mask 默认使用压缩 COCO RLE：`size=[H,W]` 和 UTF-8 `counts` 字符串 |
| 迭代精修数据 | 图片低分辨率 logits 与视频全分辨率二值 seed mask 分开定义，不共用模糊的 mask 字段 |
| 分数 | 分别表达概念置信分数、实例候选质量分数及视频分数；不承诺它们具有相同量纲或可直接比较 |
| 空结果 | 完整 SAM3 接口表达“未发现目标/无匹配结果”；不能一律伪造一个对象 0。旧接口的补零规则另行保留 |
| 引用 | 图片上下文、视频会话、任务、结果引用各有用途；不能混用同一种 ID 或把 GPU 状态作为公开 JSON |

原生图片概念框、图片实例框、视频概念框的内部格式不同，转换归适配层。对外相同的像素框格式，不代表它们具有相同的提示含义。

### 0.4 功能状态的表达

- **纳入范围**：计划通过工作流/API 交付的能力，不等于接口已上线。
- **原生基础**：当前推理源码中存在对应调用路径，仍需封装和接口级验证。
- **适配待补**：需要服务、状态管理或运行时实现，不能以原生方法返回成功代替功能验收。

本文件不公布性能指标、并发上限、视频时长限制或服务可用性承诺；这些在部署实测后填写。

## 1. 图片分割：概念模式（I02）

### 1.1 功能

- 使用文本描述查找图中符合概念的实例，例如查找所有匹配的对象，而不是只返回一个 mask。
- 使用当前图片中的正/负概念示例框，或文本与概念框组合提示。
- 在同一图片上下文中连续查询、追加示例框、清除概念提示、调整结果筛选阈值。
- 将结果中的某个实例交给 I03，继续做点/框精修。

### 1.2 输入与输出范围

| 输入内容 | 输出内容 |
| --- | --- |
| 图片或图片上下文引用；文本；带正负标签的概念示例框；概念结果筛选阈值；提示更新意图 | 原图尺寸；本轮结果引用/版本；匹配实例列表；每个实例的 mask、bbox、概念分数和可选择标识 |

需要区分“替换文本查询”“追加示例框”和“清除所有概念提示”。最终操作字段和冲突校验后续确定，不能依赖调用方猜测状态是否被保留。

### 1.3 范围限制

- 示例来自当前图片；跨图片示例迁移不在本轮承诺中。
- 一次概念查询是一个文本描述及其提示；不把多个文本类别的联合推理、去重和类别冲突处理默认列为已支持。
- 输出的多个实例与 I03 对一个目标返回的多个候选是两种结果结构。

### 1.4 部署后补充

HTTP 路径与方法、完整字段表、提示组合校验、响应结构、错误码、空结果示例、连续查询示例。

## 2. 图片分割：实例交互模式（I03）

### 2.1 功能

- 正点/负点、实例框以及点框组合定位和修正目标。
- 返回单候选，或多个候选及各自质量分数，供调用方选择。
- 通过上一轮低分辨率 logits 继续精修；可采用服务端结果引用以减少传输，具体承载方式后续确定。
- 支持同一图片上的多个独立提示组，明确每组与候选的对应关系。
- 支持概念分割结果选中后精修，复用同图上下文，并明确所选实例如何转成实例提示。

### 2.2 输入与输出范围

| 输入内容 | 输出内容 |
| --- | --- |
| 图片或图片上下文引用；提示组；正负点；实例框；可选上一轮精修数据/引用；单/多候选选择 | 原图尺寸；提示组标识；候选列表；每个候选的 mask、bbox、质量分数；后续精修所需的数据或引用 |

概念结果本身不自动等同于实例分支所需的低分辨率 logits。概念到实例的转换需明确使用所选对象的框/点击等有效提示。

### 2.3 范围限制

- 任意上传的原尺寸二值 mask，不直接当成该接口的低分辨率 logits。
- 返回候选数与识别目标数分开记录，避免调用方把多候选当成多目标。
- 旧 `/imageMask` 的单 mask 选择由兼容层另行约定，不限制完整接口返回多个候选。

### 2.4 部署后补充

提示组结构、候选选择字段、logits/结果引用格式及有效期、点框组合限制、连续交互示例。

## 3. 图片分割：上下文与提示管理（I01、I04）

| 操作 | 必要语义 |
| --- | --- |
| 创建上下文 | 载入一张图片，返回引用及原尺寸；可用于概念和实例两类操作 |
| 查询上下文 | 能判断引用是否有效，获取对应图片尺寸和状态版本 |
| 清除概念提示 | 清除概念查询相关状态；与释放图片、删除视觉特征分开 |
| 更新筛选阈值 | 明确影响哪些概念输出；不声称同时改变视频内部检测/跟踪算法阈值 |
| 释放上下文 | 释放该图片的交互状态，后续使用旧引用返回明确错误 |

一次性图片调用可以由服务自动管理上下文；多轮交互需要显式引用。有效期、资源上限、并发请求顺序在部署后明确。

## 4. 视频交互：概念提示（V02）

### 4.1 功能

- 通过文本概念或概念示例框发现视频中的匹配目标。
- 支持文本与概念框组合；返回提示帧上的多目标结果。
- 通过 V05 在视频范围内传播，保留跟踪对象 ID。
- 对发现的对象继续调用 V03/V04 修正，再继续传播。

### 4.2 输入与输出范围

| 输入内容 | 输出内容 |
| --- | --- |
| 视频会话引用；提示帧；文本；带正负标签的概念框；明确的概念查询更新意图 | 提示帧号；会话状态版本；多对象 ID、mask、bbox 和可用分数 |

### 4.3 必须明确的行为

- 概念提示与指定对象的实例修正是两种操作。当前原生概念入口会重置已有任务状态，不能包装成无副作用的“追加提示”。
- 更换概念查询时，应显式表达重新开始，并告知旧对象/结果引用的失效规则。
- 文本概念可作用于视频整体，但提交提示时只产生提示帧结果；全视频结果需要传播。
- 当前原生初始视觉提示要求一个框；不能承诺任意多初始框。正/负标签组合与纯负提示的可用边界需专门验证。
- 不要求先提交初始 mask；不能把 SAM2 旧入口“没有 mask seed 则失败/补零”的规则套用到概念分割。

### 4.4 部署后补充

路由与字段、概念更新确认字段、提示组合约束、对象 ID 生命周期、概念到实例修正的调用示例。

## 5. 视频交互：实例提示与目标管理（V03、V04、V07）

| 操作 | 必要输入 | 必要输出/行为 |
| --- | --- | --- |
| 点击初始化/修正 | 会话、帧号、对象 ID、正负点 | 更新目标并返回提示帧结果；新建对象与修正已有对象的语义应可区分 |
| mask 初始化/修正 | 会话、帧号、对象 ID、原帧尺寸的二值 RLE mask | 对指定对象注入关键帧；支持多个对象及同一对象多个关键帧 |
| 查询目标 | 会话引用 | 当前对象标识及必要状态；结果不能被误解成跨会话全局身份 |
| 移除目标 | 会话、对象 ID | 报告移除结果，并说明现有结果与后续传播受影响的范围 |

必须支持：在同一会话中“概念发现 → 选择对象 → 点击或 mask 修正 → 继续传播”。不能每次修正都重建一个丢失历史的新会话。

以下内容在字段契约阶段明确：

- 对象 ID 的创建方式、重复/不存在 ID 的处理。
- 同帧多次点击是替换还是累计；同帧重复 mask 与多个关键帧的影响顺序。
- 移除对象后哪些缓存结果失效，旧结果是否仍可作为历史版本读取。

**不列为已接通功能**：视频中按对象 ID 直接做实例 bbox 修正。当前高层视频 bbox 属于概念提示，不能用同一个字段假装已有实例框路径；若后续业务需要，单独评估适配。

## 6. 视频交互：会话、传播与结果读取（V01、V05、V06）

### 6.1 会话管理

- 创建会话：接收视频资源，返回会话引用和媒体信息（原尺寸、帧数等可用信息）。
- 查询会话：返回有效状态、状态版本和必要媒体信息。
- 重置会话：保留视频来源，清除提示、对象和跟踪状态；缓存的具体清理策略部署后说明。
- 关闭会话：释放会话资源；不能顺带销毁仍被其他会话使用的模型实例。

### 6.2 传播

输入需表达会话、方向（前向/后向/双向）、起始帧和覆盖范围。输出需表达实际完成的绝对帧号、逐帧多对象结果、操作状态及进度。

同一会话的概念发现、对象修正和传播必须操作同一份状态。相互冲突的状态修改如何排队或拒绝，部署后明确。

完整传播、局部重算、缓存读取是内部执行路径；对调用方重点保证结果版本和完成范围正确。不得把旧缓存结果当作已按新提示重新计算。

### 6.3 结果读取

支持按帧或范围读取已完成结果，明确缺失帧、尚未计算帧、无目标帧的区别。读取操作本身不隐式触发长时间传播。

结果应包含帧号、尺寸、对象 ID 与 mask；bbox 和模型可用分数按统一结果契约提供。进度、逐帧返回、最终文件之间的具体组织方式待部署确定。

### 6.4 取消（与 J03 共用）

纳入交付范围，但需要运行时适配：原生预测器存在取消应答而实际模型没有停止实现的缺口。验收必须观察传播真正停止，不能只检查返回成功。

文档最终需明确：取消请求的确认、实际终态、已完成结果是否保留、会话能否继续使用，以及取消时是否需要重置。不能默认承诺可无损续跑。

## 7. 视频离线任务与通用任务管理（J01–J03）

### 7.1 任务类型

| 类型 | 输入范围 | 输出范围 |
| --- | --- | --- |
| 概念分割任务 | 视频、文本/概念提示、处理范围、导出要求 | 多对象逐帧结果与结果产物 |
| 实例跟踪任务 | 视频、带对象 ID 的关键帧点击/mask、处理范围、导出要求 | 指定对象的逐帧跟踪结果与结果产物 |
| SAM2 兼容任务 | 旧 `/videoMask` 请求 | 旧固定单对象结果和旧回调协议 |

离线任务是对会话及传播能力的编排，不再维护一套独立推理算法。完整 SAM3 任务支持整段视频或指定区间；若按 scenes 独立运行，场景间状态与对象命名范围必须明确。

### 7.2 需要提供的管理能力

- 提交任务并获得受理结果及任务标识。
- 查询运行状态、进度、失败原因和最终结果位置。
- 获取任务完成通知/回调；新协议的触发时机、格式及失败处理部署后确定。
- 取消任务，并区分受理取消和任务已停止。
- 明确重复提交、忙碌/排队、下载上传失败和部分结果的处理规则。

旧接口继续采用文档规定的忙则拒绝和回调；新 SAM3 接口不直接继承旧单任务限制，也不在实测前承诺更高并发。

## 8. 结果格式与导出能力（E01）

| 结果类型 | 必须保留的信息 |
| --- | --- |
| 图片概念结果 | 图像尺寸、结果版本、多个实例及各自 mask/bbox/概念分数 |
| 图片实例结果 | 提示组、候选序号、候选 mask、质量分数、精修引用或数据 |
| 视频结果 | 绝对帧号、尺寸、会话/状态版本对应关系、多对象 ID 及其 mask/bbox/可用分数 |
| 异步产物 | 任务、产物类型、编码格式、资源位置；明确对象 key、文件标识或可访问 URL 的区别 |

- 二值 mask 使用压缩 COCO RLE。图片精修 logits 若需要公开，另设数据结构及传输约定。
- mask 的外接 bbox 与模型直接预测的 bbox 不混为同一来源；对外最终 mask 对应的 bbox 可统一由 mask 计算，端点细节待冻结。
- 完整视频导出必须能关联对象 ID。旧 `frame,bboxes` CSV 没有独立 ID 列，不能未经约定就将其作为多目标唯一格式。
- SAM2 兼容导出精确保留旧 JSON/CSV 结构；完整 SAM3 多目标结果另行定义，不擅自更改旧文件。
- 叠加可视化图片/视频可后续作为辅助产物；原始分割结果与可视化文件分别标识，后者不作为本轮核心 API 必选项。

## 9. SAM2 协议兼容接口

本节提取需要保留的兼容要求。完整字段与示例以公司原文为参考，部署后在交接文档中补齐并逐项验收。

### 9.1 `GET /healthz`

按旧文档返回字符串 `"OK"`。部署后的响应编码和内容类型实测记录。

### 9.2 `POST /imageMask`

| 项目 | 兼容要求 |
| --- | --- |
| 请求字段 | `kind`、`imageBase64`、`maskType`、`bboxs`、`pos_points`、`neg_points` 全部必填，不用的提示字段传空列表 |
| 提示含义 | `maskType="bbox"` 为一个实例框；其他值走点提示，至少一个正点；单目标 |
| 坐标/内容 | 原图像素坐标；base64 不带 data URL 前缀 |
| 调用方式 | 同步；模型请求依次处理 |
| 成功返回 | `code=0`、`msg`、`size=[H,W]`、`counts` 压缩 RLE |
| 失败返回 | 业务/解码错误 HTTP 200、`code=1`、`size=[0,0]`、空 counts；字段缺失/类型错误 HTTP 422 |

旧文档没有定义多候选如何选为单 mask，不能声称复刻了不可考证的旧选择算法；实现前需明确本项目规则。

### 9.3 `POST /videoMask`

| 项目 | 兼容要求 |
| --- | --- |
| 请求字段 | 保留 `taskId`、`kind`、`videoUrl`、`input`、`scenes`、`downloadTimeout`、`callbackUrl`、`storage`、`minioConfig` 的命名、类型与默认行为 |
| 视频来源 | `videoUrl` 是 bucket 对象 key；同 bucket 下载视频、上传结果；请求 minioConfig 优先于本地 storage 配置 |
| 提示 | `input` 的多个关键帧全部属于目标 0；mask 为原帧尺寸 RLE |
| 场景 | `[start,end)`、独立跟踪、只输出范围内帧；范围外 seed 忽略 |
| 无 seed 场景 | 补零 mask 和零 bbox；全部场景均无有效 seed 时按旧文档失败 |
| 受理与并发 | 立即返回 `code/msg`；成功 code 0，提交失败 code 1，已有任务 code 2；忙则拒绝，不排队 |
| 回调 | `running/succeeded/failed`、`progress`、`reason`、`output`；99/100 的含义与原文一致，最终以 status 判断成败 |
| 回调 output | JSON 字符串，二次解析得到 `masks`、`bboxs` 两个对象 key，失败时对应值为空 |
| 文件命名 | 原 videoUrl 去扩展名加 `_mask.json`、`_bbox.csv`；同视频重复提交覆盖原产物 |
| mask JSON | 逐帧 `frame`、`size`、`counts=[{object_id:0,mask:RLE}]` |
| bbox CSV | UTF-8 BOM、表头 `frame,bboxes`；bbox 覆盖 mask 全部连通区域，空 mask 为全零 bbox |
| 回调失败 | 按旧文档的任务失败行为处理，并释放任务占用；不能直接套用不同的通用回调策略 |

默认回调地址、存储配置格式和超时默认值在正式字段表中按原文列出并由部署配置核验；本草案不执行任何公司回调或存储访问。

旧文档还记录了 `kind` 非 videoMask 时不处理却回调成功的特殊行为。将其保留在兼容验收清单，具体保留策略需明确；完整 SAM3 新接口不自动继承该行为。

100 帧分批、50 帧重叠、末尾 3 帧接续是旧 SAM2 实现说明，不作为 SAM3 公共接口参数或固定实现承诺。

### 11.1 实现前需要明确的契约

| 项目 | 待明确内容 |

现有源码基础有三处特别需要补齐验证：取消可能仅返回应答；部分外层提示/阈值参数会被底层签名过滤；存在图片 batch 方法不代表概念处理整条调用链支持 batch。这些属于实现任务，不改变主功能范围。

### 11.2 主要功能验收清单

- 图片文本概念、正负概念框、文本与框组合、多实例及无匹配结果。
- 图片正负点、实例框、点框组合、多候选、低分辨率 logits 连续精修。
- 同图概念结果选中后实例精修，结果与上下文对应正确。
- 视频文本/概念框初始化、多目标发现；概念更换后的状态失效符合约定。
- 视频多对象、多关键帧点击/mask 修正，概念发现与修正在同一会话串联。
- 前向/后向/双向传播，范围和绝对帧号正确；修正后结果与旧缓存不混用。
- 对象移除，会话重置/关闭，任务取消确实生效；操作后的资源与状态符合约定。
- 多目标 RLE 和文件结果可还原；对象、帧和候选关系不丢失。
- SAM2 图片/视频的字段、同步/异步、回调、忙碌语义、场景补零和结果文件逐项对齐。

这些是待执行的接口验收要求。此前原生推理迁移的样例对照，不替代本清单的服务级验收，也不证明 SAM3 与 SAM2 预测结果数值一致。
